# 断缝储_裂缝样本生成

这是一个面向油气裂缝研究的脚本型项目，核心工作不是单一模型训练，而是一整条数据处理与建模链路：

1. 读取测井、井斜、时深、成像测井和 SEG-Y 地震数据
2. 构建井周地震-测井联合样本
3. 依据 FMI/解释结果生成裂缝标签
4. 训练裂缝存在性、位置、角度预测模型
5. 构建局部 DFN，融合断层与裂缝片
6. 将 DFN 体素化，并尝试使用 3D-GAN 从地震块生成裂缝体

当前仓库更接近“研究脚本集合”，还没有完全工程化。为了在不破坏现有脚本的前提下提升可维护性，本次先补充结构说明和后续整理方案。

## 当前目录职责

- `数据精简/`
  - 井周样本构建
  - trace 头信息整理
  - 裂缝标签生成
  - 若干统计和检查脚本
- `模型训练/`
  - 裂缝存在性分析
  - 裂缝位置分析
  - 裂缝角度预测
  - 包含 XGBoost、LSTM 等方案
- `小范围DFN生成/`
  - 单元地震信息抽取
  - 井所在单元 DFN 构建
  - 断层裂缝片生成与融合
  - 若干三维可视化脚本
- `研究内容三/`
  - DFN 体素化
  - 训练数据生成
  - 3D-GAN 训练与推理
  - 单元 DFN 合并和体素/网格互转
- 根目录脚本
  - 偏向原始文件读取、数据检查和独立实验

## 建议的目标工程结构

建议后续逐步收敛到下面的结构，而不是一次性大搬家：

```text
.
|-- README.md
|-- requirements.txt
|-- configs/
|   `-- paths.example.yaml
|-- docs/
|   `-- restructure_plan.md
|-- scripts/
|   |-- audit/
|   |-- dataset/
|   |-- train/
|   |-- dfn/
|   |-- voxel/
|   `-- gan/
|-- src/
|   `-- fracture_sample_gen/
|       |-- io/
|       |-- preprocessing/
|       |-- labeling/
|       |-- features/
|       |-- models/
|       |-- dfn/
|       |-- voxel/
|       `-- utils/
|-- data_index/
|-- outputs/
`-- legacy/
```

说明：

- `scripts/` 保留“可直接运行”的入口脚本
- `src/` 收敛可复用函数，减少重复代码
- `configs/` 统一绝对路径和实验参数
- `outputs/` 统一模型、图件、日志、临时结果
- `legacy/` 用来承接暂时不改造的历史脚本

## 推荐整理顺序

按风险从低到高，建议这样推进：

1. 先统一路径配置，去掉脚本里的 `E:` 盘硬编码
2. 再把重复的文件读取逻辑抽到 `src/`
3. 然后为样本构建、标签构建、训练分别补统一入口脚本
4. 最后再考虑移动历史脚本目录

## 当前不建议直接做的事

- 不建议一次性批量移动现有脚本
- 不建议直接改动全部中文目录名
- 不建议先做大规模面向对象重构

原因是当前很多脚本直接依赖固定路径和中间产物，贸然移动很容易把研究链路打断。

## 关键研究链路

可以先把项目理解为这几段：

```text
原始数据检查
  -> 地震/测井关联
  -> 井周样本构建
  -> 裂缝标签生成
  -> 裂缝预测模型训练
  -> 局部 DFN 生成
  -> DFN 体素化
  -> 3D-GAN 训练与生成
```
