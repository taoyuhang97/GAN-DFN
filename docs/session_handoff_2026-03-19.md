### 4.2 当前总体思路

2. 再根据密度把裂缝发育段离散为裂缝点位

## 5. 裂缝密度预测

### 5.1 核心脚本

- `模型训练\优化阶段一\裂缝位置分析\基于密度的裂缝点位分析\fracture_density_predict.py`

### 5.2 脚本定位

- 使用 CNN + LSTM 做裂缝密度回归
- 输入仍是“地震 + 测井属性”
- 训练样本不再使用全量样本，而是仅关注“有裂缝密度标注的裂缝样本”
- 最初尝试同时预测 `P10 / P21 / P33`
- 后续已调整为以 `P10` 为主目标

### 5.3 当前 target 处理

- 先做 `log1p(raw * scale)`
- 再做 `StandardScaler`

### 5.4 当前结论

- 当前跨井回归效果仍然较差，`R²` 整体偏低，甚至出现负值
- 模型更像是在输出平滑常数，而没有稳定学到“中间大、两边小”的密度形态
- 因此不能过度依赖当前逐点密度回归结果

## 6. 裂缝点位精细化

### 6.1 核心脚本

- `模型训练\优化阶段一\裂缝位置分析\基于密度的裂缝点位分析\fracture_point_refine_by_density.py`

### 6.2 当前实现逻辑

- 对裂缝段内的密度做积分，将密度视为强度函数
- 先得到每个裂缝段的总强度
- 再通过“等累计强度”方式在段内布点
- 支持用 `PRED_PROB^gamma` 对段内强度做再分配
- 这样可以让高概率区域点更密、低概率区域点更疏

### 6.3 当前评价指标

- `N_gt_points`
- `N_pred_points`
- `count_diff`
- `pred_to_gt_mean_dist / median / p90`
- `gt_to_pred_mean_dist / median / p90`

## 7. 原始裂缝密度标签的生成逻辑

### 7.1 来源脚本

- `数据精简\优化阶段一\new_fracture_exist_sample.py`
- `数据精简\优化阶段一\new_fracture_exist_sample_other.py`

### 7.2 已核对结论

- 两份脚本的核心逻辑都是按深度做一维线性插值
- `new_fracture_exist_sample_other.py` 先把原始密度文件反转为“浅到深”后再插值
- 这个反转是合理的，因为原始 `txt` 密度文件本身是“深到浅”排序

### 7.3 当前需要注意的潜在问题

- `new_fracture_exist_sample_other.py` 中会把 `-999.25` 缺失先视为缺失，再 `fillna(0)`
- 这等价于默认“缺失 = 零密度”
- 如果地质语义上“缺失”更接近“未知”，那么这里可能会对标签造成偏差

## 9. 最近完成的重要代码修改

### 9.1 对 `fracture_density_predict.py` 的修改

现在会同时输出两类预测列：

- `P10_PRED_RAW`
  - 对所有可形成序列中心点保存原始预测值
- `P10_PRED`
  - 默认只在 `CENTER_HAS_DENSITY = 1` 的位置保存预测值

这样做的原因：

- 人工查看结果时，不会再错误理解成“全井段都有裂缝密度”
- 下游点位算法仍可读取完整原始预测，再由裂缝段结果做门控

### 9.2 对 `fracture_point_refine_by_density.py` 的修改

- 默认读取 `P10_PRED_RAW`
- 同时保留对旧日志的兼容：
  - 若新日志存在 `P10_PRED_RAW`，优先使用
  - 若只有旧字段 `P10_PRED`，也可继续读取

## 11. 当前最重要的技术判断

当前第二部分的主要瓶颈不是“点位离散算法本身”，而是：

- 逐点密度回归效果太弱
- 第一部分裂缝段预测仍有漏检和偏差

因此更合理的路线是：

1. 先用第一部分得到较稳定的裂缝段结果
2. 在预测裂缝段内使用密度或概率做段内重分配
3. 优先依赖“段级总量标定 + 段内概率形状分配”
4. 不要强行要求 LSTM 直接恢复真实逐点密度曲线
