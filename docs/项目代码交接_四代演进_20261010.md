| 代次 | 时间 | 代码位置 | 一句话定位 | 代表版本/产物 |

### 1.1 为什么要一代代改

1. **①→②**：初版是"先随机生成裂缝片、再靠地震属性和断层做大规模后修正"，
   结果对后处理参数过于敏感、地质可解释性差；第一轮改进把监督前移，
   改成"成像监督 → 分层专家库 → 常规测井两阶段预测"，先把**井上约束**做扎实。
2. **②→③**：第一轮改进的产物是"单元级"的，尺度碎、跨单元不连续；
   第二轮改为**矿区尺度**：统一 T4–T7 层位合同、300 m/多尺度证据体、
   分尺度 DFN 生成与融合、井控校正，并补齐剖面与密度量化展示。
3. **③→④**：太古界的层位（上部复合层顶/太古界顶/风化壳底）、深度基准（MD）、
   属性体（OBN 三属性）都与砂砾岩不同，**框架复用、口径必须重写**。

## 2. 第一代：砂砾岩原始方案

### 2.1 主流程逻辑

按立项方案拆成三个研究内容，串行关系为：

```
成像测井样本 → 分层专家模型库 → 常规测井两阶段裂缝预测
   → 井间虚拟测井与单元裂缝归属 → 单元 DFN
   → 区域 DFN 合并与后处理 → 区域断层后融合
```

### 2.2 目录与主脚本

| 环节 | 目录 | 主要脚本 |
|---|---|---|
| trace 头 / 坐标基准 | `数据精简/` | `read_trace_header_xy.py`、`XY_coordinate_statistics.py` |
| 井周地震-测井样本 | `数据精简/` | `data_around_well.py`、`well_related_trace_curve.py`、`well_related_trace_id.py` |

### 2.3 主要问题（被后续代次替换的原因）

- 单元尺度碎、跨单元不连续，边界处裂缝对不上；
- "随机生成 → 大规模后修正"权重难定，结果对参数敏感；
- 断层只当后处理叠加，没有在前端参与格局控制；
- 缺少统一层位合同，各步骤各按自己的深度口径。

## 10. 已知坑与注意事项

1. **仓库是 public**：`优化阶段二/提交材料/`（汇报/结项材料）与
   `优化阶段二/正式主线/专利思考/`（专利交底书）**不得入库**，已在 `.gitignore` 排除；
   专利文档在申请前公开会破坏新颖性。
2. **生成产物不入库**：`**/output/`、`**/outputs/`、活动日志、
   `太古界/dfn_display_zflip_*/`（VTK 展示包约 400 MB）、`太古界/_archive_*/` 均已忽略。
3. **外部数据不在仓库**：`/data/shared/project-oil/wx数据/砂砾岩/` 与 `.../埕岛太古界/`
   需在接手环境另行配置；`优化阶段二/正式主线/logs/` 也只记运行日志。
4. **禁止覆盖历史版本目录**：新运行必须复制新版本名（如 `..._v3`），
   否则 Step8/Step9 的验收会与旧结果混淆。
5. **两套虚拟井数字别混用**：对外讲砂砾岩请用正式主线 **38 井 / 950 条**（§7.2）。
6. **时间域/深度域勿混**：地震与 DFN 均为 TWT（ms）；
   砂砾岩展示 Z=+|TWT|，Z 镜像包为负值仅用于 ParaView 展示；
   太古界成像解释深度是**测深 MD**，不是 TVD。
7. **OBN 道头坐标有 ±1 m 取整抖动**：不要用唯一值差分求道距，
   用"外接矩形面积 ÷ 总道数"（太古界 step9b 已按此实现）。
8. **ASCII VTK 无法表达 NaN**：写出端会把 NaN 打成字面量 `nan`，读取端（含 ParaView）
   会解析错位并丢数组；太古界 `build_taigu_zflip_display_bundle.py` 已在写 ASCII 前把非有限值置 0。
