# 第四步第五步 Demo 主线

## 1. 文档目的

本文档用于固定当前小范围 demo 的实现主线，解决下面两个问题：

1. 第四步的输出对象到底是什么；
2. 第五步在 demo 阶段应该如何承接第四步，而不是继续停留在抽象描述。

这里不讨论最终矿区尺度的完整区域识别算法，只固定当前 demo 的可执行链路。

## 2. 当前已经锁定的前置输入

当前默认前置输入来自第二步和第三步。

### 2.1 第二步

第二步已经固定为：

- `T4-T6 -> 沙三专家库`
- `T6-T7 -> 沙四专家库`
- 主输出是连续裂缝密度曲线

### 2.2 第三步

第三步已经固定为：

- 每口真实井定位一个中心参考道
- 在主地震网格上取 `5x5` 邻域
- 在 `T4-T7` 时间窗内提取多属性
- 生成近井虚拟井控弱标签样本

因此，第四步和第五步不需要再去讨论如何产生样本，而是直接承接第三步的统一样本表。

## 3. 第四步的正式 demo 输出对象

第四步在当前 demo 阶段只输出两类东西。

### 3.1 关系明细表

文件：

- `relation_bins.csv`

含义：

- 对每个 `layer_group + attribute`
- 做分箱统计
- 输出每个分箱对应的裂缝密度均值和离散程度

它回答的是：

- 某层位下，某个属性从弱到强变化时，裂缝密度大体如何变化。

### 3.2 关系摘要表

文件：

- `relation_summary.csv`

含义：

- 对每个 `layer_group + attribute`
- 输出样本数、有效样本数、加权相关系数等摘要

它回答的是：

- 该属性在本层位是否值得保留；
- 保留后在第五步里应赋予多大权重。

### 3.3 为什么第四步先停在这一步

因为当前最需要固定的是“关系如何表达”，而不是直接做全区推广。

如果第四步连输出对象都没有固定，后面第五步、局部规则法和局部 GAN 都无法统一承接。

## 4. 第五步 demo 的正式输入对象

第五步 demo 当前只接受三份输入：

1. 第三步统一样本表；
2. 第四步 `relation_bins.csv`；
3. 第四步 `relation_summary.csv`。

这三份文件一旦齐全，第五步 demo 就能开始，不再依赖其他抽象判断。

## 5. 第五步 demo 的正式输出对象

第五步 demo 当前输出两类核心对象。

### 5.1 样点控制分数表

文件：

- `scored_samples.csv`

含义：

- 仍然按第三步统一样本表的样点组织
- 为每个样点补充：
  - 每个属性映射得到的局部裂缝评分
  - 多属性融合后的 `ControlScoreRaw`
  - 与第三步弱标签融合后的 `ControlScore`

它回答的是：

- 同一个空间样点，在第四步关系约束下，局部裂缝发育倾向多大。

### 5.2 局部控制场

文件：

- `local_control_field.csv`

含义：

- 按 `LayerGroup + X + Y + TIME` 聚合
- 得到局部空间上的裂缝发育控制分数

它回答的是：

- 在 demo 范围内，哪些位置明显更可能属于裂缝发育区域；
- 哪些位置较弱；
- 第四步关系是否真的能落回空间对象。

## 6. 当前 demo 的完整链路

当前小范围 demo 主线固定为：

```text
车页1导眼 井周 5x5 + T4-T7 范围抽检
-> 构造第三步统一样本表
-> 第四步生成 relation_bins / relation_summary
-> 第五步映射为 scored_samples / local_control_field
-> 用 local_control_field 作为后续区域识别或局部生成入口
```

其中：

- 当前 demo 井固定为 `车页1导眼`
- 不再额外设置第二口 demo 井
- 若后续要补第二口井，只能选择与矿区主地震和新增属性体处于同一坐标体系、且能稳定对齐的井

这样处理的原因已经明确：

- `车662` 不在当前矿区新增蚂蚁体、相干体、曲率体、裂缝反演数据的稳定对齐范围内；
- 如果继续拿 `车662` 做 demo，会导致第三步统一样本表从源头上就存在空间错配风险；
- `车页1导眼` 本身就是当前第二步已固定的唯一外层验证井，且在现有项目口径里属于矿区范围内关键验证井。

因此，当前 demo 必须围绕 `车页1导眼` 单井闭环展开，而不是“先用别的井跑通，再回来补验证井”。

## 7. 基于车页1导眼的 demo 设计口径

### 7.1 空间范围

当前 demo 的空间范围固定为：

- `车页1导眼` 对应主地震最近参考道；
- 以该参考道为中心的平面 `5x5` 邻域；
- 其中中心道代表真实井参考位置，其余邻域道作为第三步候选虚拟井位置。

### 7.2 垂向范围

当前 demo 的垂向范围分两层理解：

第一层是地质目标范围：

- 仍然固定为 `T4-T7`

第二层是当前这口井在现有资料中的工程约束范围：

- `车页1导眼` 已明确上下界为 `3500 m` 和 `3750 m`

因此，真正做 demo 时，应先以 `车页1导眼` 的时深关系和 `around_data` 为准，确定该井在 `T4-T7` 内实际落入的有效样点区间，而不是默认整段全部可用。

### 7.3 第三步样本来源

当前 demo 的第三步统一样本表，应优先基于 `车页1导眼` 现有正式链路中的基础底表组织：

- 井斜目录下统一采样的 `around_data`
- 第二步输出的该井连续裂缝密度曲线
- 该井对应的分层结果
- 主地震最近参考道与 `5x5` 邻域的空间索引关系

也就是说，这次 demo 不应从零散原始文件重新随意拼表，而应尽量沿用你们现有 `around_data -> 裂缝密度 -> 分层 -> 井周属性` 这条正式链路。

### 7.4 当前 demo 可使用的属性集合

基于 `车页1导眼` 当前的对齐条件，demo 阶段应把属性分成两类。

第一类是默认主用属性：

- `SEIS_TRUE`
- `COHERENCE`
- `ANT_TRACK`
- `CURVATURE_MAX`
- `CURVATURE_POS`

第二类是条件使用属性：

- `FRACTURE_INV`
- `FaultDistance`

原因是：

- 裂缝反演体本身覆盖范围与其它属性体不完全一致，且是 `T5-T7` 范围；
- 因此在 `车页1导眼` demo 中，`FRACTURE_INV` 只能按“有覆盖则取值、无覆盖则留空”的口径使用；
- `FaultDistance` 当前如果还没有稳定产出，则字段先预留，不阻塞样本表构造。

### 7.5 第四步 demo 的最小目标

围绕 `车页1导眼` 的第四步 demo，不追求一次做成矿区规律，只要求回答三个问题：

1. `车页1导眼` 井周小范围样本表是否能稳定构造；
2. 在该井 `T4-T7` 有效区间内，属性与裂缝密度是否能产出可解释的 `relation_bins / relation_summary`；
3. 哪些属性在这口井周边的小范围样本中具备保留价值，哪些应该先降级为空列或辅助列。

### 7.6 第五步 demo 的最小目标

围绕 `车页1导眼` 的第五步 demo，也只要求回答三个问题：

1. 第四步关系表能否重新映射回这口井周边的样点；
2. 能否生成局部 `ControlScore`；
3. 该局部控制分数场是否能把井周相对更有利和更不利的位置区分开。

也就是说，当前 demo 的成功标准不是“已经识别出完整裂缝发育带”，而是：

- 第四步关系结果不再停留在表格层面；
- 第五步已经能把它变成真实的空间控制对象。

## 8. 为什么第五步 demo 不直接做全区裂缝发育带

因为当前样本基础还不够支撑直接做可靠的矿区尺度区域划分。

如果现在直接跳到全区裂缝发育带识别，会同时暴露三类问题：

- 第四步关系本身还没被验证能否稳定落回空间；
- 第三步样本表字段和缺失属性处理还在收敛；
- 断层、属性缺失和局部覆盖不足会让全区结果难以解释。

因此，当前更合理的做法是：

- 先在 `车页1导眼` 周边小范围内验证这条关系映射链；
- 证明第四步输出不是“只能看不能用”的汇报表；
- 再往更大范围推广。

## 9. 与后续 GPU / GAN 的关系

当前第四步和第五步 demo 虽然主要是表格和局部控制场，但设计时已经预留了后续 GPU 化路径。

### 8.1 GPU 化第一优先级

不是直接训练 GAN，而是先把以下对象稳定下来：

- 第三步统一样本表
- 第四步关系表
- 第五步局部控制场

因为这些对象稳定之后，后续才能做批量 patch 化。

### 8.2 局部 GAN 更适合放在哪

当前更合理的放置位置不是第四步，也不是第五步关系校准阶段，而是更靠后的局部生成阶段。

推荐口径是：

- 第四步：关系校准
- 第五步：局部控制场 / 发育倾向场
- 第六步：在控制场约束下做局部 patch 级生成

这样 GAN 的输入会更明确：

- 多属性 patch
- 断层距离或控制分数字段
- 第五步局部控制场

输出也更明确：

- 局部裂缝密度块
- 或局部初始 DFN 参数块

## 10. 当前 demo 结束后下一步该做什么

当前小范围 demo 跑通后，下一步应按下面顺序推进：

1. 固定第三步统一样本表正式字段名；
2. 基于 `车页1导眼` 真数据构造一版小范围统一样本表；
3. 用这版真样本顺序跑一次第四步和第五步 demo；
4. 再讨论第五步区域扩展或第六步局部受控生成。

## 11. 一句话总结

当前第四步到第五步的小范围 demo 主线已经固定为：

`车页1导眼井周统一样本表 -> 分层关系表 -> 样点控制分数 -> 局部控制场`

先把这条链跑通，再谈矿区尺度扩展，顺序上才是稳的。
