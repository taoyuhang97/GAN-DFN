# 裂缝密度预测实验方案汇报重点版

## 1. 研究问题

本研究面向地下裂缝发育强度预测。实际场景中，成像测井能够提供较可靠的裂缝解释，但井数量少、空间覆盖有限；地震、相干、断层、层位等数据覆盖范围广，但不能直接提供裂缝密度标签。

因此，本文拟研究的问题是：

> 在少量井控裂缝观测和多模态地震结构信息约束下，预测二维剖面或目标层面的连续裂缝密度/裂缝发育强度场。

从计算机领域角度，可抽象为：

> 极少量一维观测 + 多模态结构图像条件下的二维连续密度场预测。

主输出是连续裂缝密度/发育强度图；高裂缝发育区是由连续密度图阈值化得到的辅助评价结果。

## 2. 实验设计困难

当前实验设计的核心困难是数据不完整。

1. 私有油田数据不能公开，原始地震剖面、井位、成像测井解释结果等具有保密限制。
2. 公开数据中缺少“成像测井裂缝解释 + 地震/相干结构属性 + 区域二维裂缝密度真值”的完整组合。
3. 计算机论文需要可复现实验、强基线对比和消融分析，仅依赖私有留一井指标说服力不足。

因此，不能用单一数据集完成全部验证，需要建立分层实验策略。

## 3. 总体数据策略

实验采用三层证据链：

| 数据类型 | 作用 | 边界 |
|---|---|---|
| 自建可公开合成数据 | 提供完整二维真值，支撑主实验、消融实验和鲁棒性实验 | 只能证明算法机制，不能直接证明真实油田预测准确 |
| 公开地震结构数据 | 验证少标签、弱标签、结构传播等可复现机制 | 多数不是裂缝密度任务，只能作为代理验证 |
| 私有真实油田数据 | 验证真实场景下未见井/未见层段的预测能力 | 只能公开匿名指标，不能证明完整二维图处处正确 |

核心表述应是：

> 合成数据证明机制，公开数据证明相关机制可复现，私有数据证明真实场景可用。

## 4. 方法与实验要验证的问题

本文方法建议定位为：

> 基于半监督 dense prediction 框架的结构约束弱标签增强方法。

主要模块与实验问题对应如下：

| 方法模块 | 需要验证的问题 |
|---|---|
| 稀缺井控 masked regression | 少量井控观测能否约束二维密度预测 |
| 近井结构约束虚拟井控 | 虚拟井控弱标签是否有效 |
| 置信度门控 | 能否避免错误虚拟标签误导模型 |
| 多模态结构条件融合 | 地震、相干、断层、层位等结构信息是否有效 |
| 稀缺鲁棒机制 | 井控极少、分布偏置或含噪时是否更稳定 |

需要明确：backbone、基础一致性训练、普通 masked regression 不是主要创新；本文重点应放在虚拟井控生成、置信度门控、多模态结构约束和稀缺井控实验协议上。

## 5. 主体实验设计

建议将实验分为主体实验和增强实验。

### 主体实验

| 实验 | 目的 | 主要数据 |
|---|---|---|
| E1 整体有效性 | 验证少量井控 + 多模态结构条件能否预测二维密度场 | 自建合成数据 + 私有留一井 |
| E2 虚拟井控消融 | 验证虚拟井控弱标签和置信度门控是否有效 | 自建合成数据 + CRACKS 代理 |
| E3 多模态结构消融 | 验证地震、相干、断层、层位等结构条件是否有贡献 | 自建合成数据 + OpenFWI/F3/Penobscot 辅助 |
| E5 私有真实验证 | 验证真实场景下未见井/未见层段泛化能力 | 私有真实油田数据 |

### 增强实验

| 实验 | 目的 | 主要数据 |
|---|---|---|
| E4 稀缺鲁棒性 | 验证井数少、标签偏、噪声强时方法是否退化更慢 | 自建合成数据 + FaultSeg3D/CRACKS/Thebe |
| 公开代理任务 | 补充可复现机制验证 | OpenFWI、FaultSeg3D、CRACKS |

最低可实施闭环建议为：

> E1 合成主实验 + E2 虚拟井控消融 + E3 多模态消融 + E5 私有 leave-one-well-out。

## 6. 公开数据集使用定位

公开数据不能直接证明真实裂缝密度预测效果，只能作为机制代理验证。

| 数据集 | 定位 | 用法 |
|---|---|---|
| OpenFWI | 强代理 | 从少量一维采样恢复二维速度/结构属性，验证少标签二维场重建 |
| FaultSeg3D | 中等代理 | 将完整断层标签降采样为少量线状/点状标注，验证结构传播 |
| CRACKS | 机制代理 | 使用不同质量标注和置信度信息，验证弱标签/置信度门控 |
| Thebe | 辅助代理 | 验证真实地震结构少标签泛化 |
| F3 Netherlands / Penobscot | 辅助数据 | 验证真实井震多模态输入组织，不作为主任务定量验证 |

## 7. 自建合成数据要点

自建合成数据用于提供完整二维真值，支撑 E1-E4。

基本流程：

1. 生成二维地质结构背景：层位、断层、构造起伏、岩性分区和非均质噪声；
2. 根据断层邻近性、层位曲率、构造梯度、岩性敏感性和空间随机场生成裂缝密度真值；
3. 派生地震、相干、断层概率、层位距离、曲率等结构输入；
4. 从完整真值中抽取少量井线作为真实井控观测；
5. 在真实井附近生成带置信度的虚拟井控弱标签。

为避免“自证有效”，需要：

1. 设置 ID、扰动和 OOD 三类测试；
2. 保留隐藏因子，不把所有标签生成因子都作为输入；
3. 使用多套生成器和随机参数范围；
4. 对输入模态加入噪声、缺失、模糊和错位；
5. 尽量基于 OpenFWI、Marmousi 等公开结构模型派生部分样本；
6. 公开生成代码、参数范围和随机种子。

## 8. 虚拟井控验证重点

虚拟井控不能被当作真实标签，只能作为近井范围内的低置信弱标签。

构造原则：

1. 只在真实井附近有限范围内生成；
2. 不跨越断层或强结构不连续边界；
3. 优先沿层位方向或局部构造连续方向传播；
4. 距离越远置信度越低；
5. 构造复杂或模型不确定区域降低置信度。

E2 需要比较：

| 组别 | 设置 |
|---|---|
| A | 只用真实井控 |
| B | 真实井控 + 无权重虚拟井控 |
| C | 真实井控 + 距离权重 |
| D | 真实井控 + 距离 + 结构边界 |
| E | 真实井控 + 距离 + 结构边界 + 不确定性门控 |
| F | 过范围虚拟井控 |

期望结论：带置信度的虚拟井控优于无虚拟和无权重虚拟；过范围虚拟井控应表现出退化风险。

## 9. 对比方法与公平性

对比方法需要分层设置。

| 类型 | 方法 |
|---|---|
| 空间估计 | Regression Kriging、Co-Kriging |
| 深度回归 | U-Net masked regression、SegFormer/Swin-UNet masked regression |
| 半监督/弱监督 | Mean Teacher、UniMatch V2 baseline、U2PL、scribble/partial-label 方法 |
| 代理任务基线 | FaultSSL、FaultSeg、Seismic Fault SAM |
| 消融版本 | 无虚拟井控、无置信度、无结构边界、无一致性正则、单模态输入 |

公平性要求：

1. 所有方法使用相同训练/验证/测试划分；
2. 所有方法使用相同真实井控 mask；
3. 主实验中深度模型使用相同结构输入；
4. 至少 3 个随机种子，报告均值和标准差；
5. 区分“公平输入对比”和“模块增益对比”。

## 10. 实现路线

不建议从零实现完整系统。建议先做最小闭环，再接入复杂半监督框架。

实施顺序：

1. 实现自建合成数据生成器；
2. 实现 U-Net 或 SegFormer masked regression 最小基线；
3. 实现虚拟井控生成模块；
4. 完成 E1/E2/E3 的最小合成实验；
5. 完成私有数据 leave-one-well-out 验证；
6. 再评估是否接入 UniMatch V2 或其他半监督框架；
7. 根据时间补充 OpenFWI、FaultSeg3D、CRACKS 代理任务。

UniMatch V2 可作为候选主框架，但不是唯一主线。原因是它原本是半监督语义分割方法，改成连续密度回归需要验证适配成本。更稳妥的路线是：先用 U-Net/SegFormer 完成最小闭环，再迁移到 UniMatch V2。

## 11. 私有数据验证注意事项

私有数据只能验证未见井/未见层段泛化，不能直接证明完整二维图全局正确。

需要注意：

1. leave-one-well-out 时，留出井不能参与真实井控训练；
2. 留出井也不能参与虚拟井控生成；
3. 必要时在留出井周边设置虚拟井控排除缓冲区；
4. 如果井数少，需要明确统计局限；
5. 报告每口留出井指标、均值、标准差和分裂缝强度区间误差；
6. 如条件允许，补充 leave-one-interval-out。

## 12. 待确认事项

正式开展实验前，需要确认：

| 待确认事项 | 影响 |
|---|---|
| 合成数据采用纯程序生成，还是部分基于 OpenFWI/Marmousi 派生 | 影响合成数据可信度 |
| 私有数据中可用于 leave-one-well-out 的成像测井数量 | 影响真实验证统计可靠性 |
| 主实验固定为二维剖面还是目标层平面 | 影响输入输出格式和数据预处理 |
| 是否允许设置留出井周边虚拟井控排除缓冲区 | 影响防泄漏协议 |
| UniMatch V2 改连续回归的成本是否可接受 | 影响主框架选择 |
| 公开代理任务优先选择 OpenFWI 还是 FaultSeg3D | 影响公开实验工作量 |
| CRACKS 是否容易获取和预处理 | 影响弱标签代理实验 |
| 私有数据是否允许展示脱敏局部统计图 | 影响真实应用验证的可解释性 |

## 13. 汇报时应强调的结论

建议汇报时强调以下几点：

1. 我们的论文实验不能只依赖私有数据，因为私有数据不能公开且没有完整二维真值；
2. 公开数据也不能直接证明裂缝密度预测，因为缺少成像测井裂缝解释和区域裂缝密度真值；
3. 因此必须采用“自建合成数据 + 公开代理任务 + 私有真实验证”的分层证据链；
4. 自建合成数据用于完整任务和消融验证，公开代理任务用于可复现机制验证，私有数据用于真实场景适用性验证；
5. 最小可实施闭环是 E1、E2、E3 和 E5；
6. 当前最大风险是合成数据说服力、公开代理任务间接性和私有数据验证范围有限。
