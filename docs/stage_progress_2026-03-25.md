## 2. 当前项目的整体想法

### 2.1 总目标

项目总目标是通过生成式方法构建矿区尺度的 DFN 模型。当前工作属于“优化阶段一”，重点是先把井上的裂缝信息做稳定、做可迁移，再为后续 DFN 提供基础输入。

### 2.2 当前统一后的三部分路线

#### 第一部分：扩充矿区裂缝样本库

目标是把已有常规测井上的裂缝尽可能标出来，使矿区的裂缝样本从少量成像井扩展到更多测井。

当前拆成三个连续子任务：

1. 基于地震数据 + 常规测井属性预测裂缝发育段
2. 基于裂缝发育段进一步细化裂缝发育点位
3. 在点位基础上继续预测裂缝密度、倾向和倾角

这三步分别解决：

- 裂缝发育段：哪里可能有裂缝
- 裂缝点位：具体在什么位置、有多少条
- 裂缝密度：裂缝发育强度有多强，后续裂缝片应偏大还是偏小
- 倾向倾角：裂缝片应朝哪个方向延伸、如何倾斜

#### 第二部分：构建用于 GAN 训练的单元级 DFN 样本

当前统一后的理解是：

1. 先对矿区做单元划分
2. 对缺少实测测井的单元，先用地震数据及周边常规测井信息构建虚拟测井
3. 再把第一部分的方法应用到虚拟测井，得到裂缝分布
4. 对于单元内部，还可结合地震梯度异常和最近井裂缝属性迁移，补充单元尺度裂缝分布
5. 将单元裂缝结果表达为体素化 DFN
6. 体素化 DFN 中需要能表达位置、密度或强度、倾向倾角
7. 最后再把体素化结果转换为离散裂缝片，并结合层位约束对跨层裂缝片进行切割和修正

#### 第三部分：基于已有单元 DFN 生成整个矿区 DFN

当前统一后的理解是：

1. 以已有单元 DFN 和地震响应为训练样本
2. 学习“地震特征 -> DFN 表征”的映射
3. 补全其他单元的 DFN
4. 最后做跨单元边界对齐与整体拼接
5. 得到矿区尺度 DFN

### 2.3 当前更符合石油地质思路的约束方式

结合前期讨论，当前路线强调以下几点：

- 以地层作为第一层组织框架，而不是先把所有井段混在一起建统一模型
- 裂缝预测结果首先服务于地质解释，再服务于 DFN 构建
- 裂缝密度不再只被理解为“布点权重”，而是后续裂缝片尺度约束量
- 断层影响当前阶段先不纳入主流程，待单元 DFN 构建完成后再做统一叠加和修正

目前已知地质框架信息里，层位界面数据相对明确，岩性和力学层信息不足，因此当前合理的主线是：

- 先按地层组织样本与模型
- 先把井上裂缝分布做稳
- 后面再把断层影响作为整体 DFN 的后处理约束引入

## 3. 第一部分当前进展

- 地震属性
- AC
- GR

原因是此前对比发现，在当前样本条件下，更多常规测井属性并没有带来稳定提升，而使用“地震 + AC + GR”后可以把样本由原来的 4 个井段扩展到 6 个井段。

### 3.2 第二步：裂缝点位细化

#### 当前方法已经发生的关键变化

当前第二步已经从“逐点密度回归恢复真实裂缝形态”的思路，转向以下主线：

1. 先用第一步结果圈定预测裂缝发育段
2. 对每个预测段构建段级特征
3. 预测该段应细化出多少条裂缝
4. 再在段内按概率形状分配具体点位

也就是当前主线是：

`发育段门控 -> 段级总量标定 -> 段内概率分配`

而不是：

`直接逐点回归真实密度曲线`

#### 当前第二步核心脚本与包装脚本

- 核心脚本：`模型训练/优化阶段一/裂缝位置分析/基于密度的裂缝点位分析/raw_point_guided_segment_refine.py`
- 分层包装脚本：`run_manual_strata_raw_point_refine.py`

#### 当前第二步已完成的主要改动

已完成的主要改动包括：

- 引入原始离散裂缝点和发育段共同构建段级训练样本
- 引入边界补偿 `prob_shoulder`
- 引入段级总量标定与规则回退
- 引入选择性后处理下调
- 新增 `count_error_pct` 和 `overall_count_error_pct`
- 新增训练井距离加权开关
- 新增 `count_bin` 逻辑，用于对段级裂缝条数做分档约束
- 新增 `PredDensityStrength`
- 新增 `PredDensitySizeScale`
- 新增 `PredDensityStrengthLevel`

这组新增字段的意义是把当前第二步结果进一步向后续 DFN 需求靠近，即：

- 不只输出“点位”
- 还开始输出可用于表征裂缝强度和裂缝片尺度等级的辅助量

### 3.3 第一部分当前的统一判断

当前第一部分已经形成如下统一认识：

- 第一步更适合被定义为“候选裂缝发育段识别”

## 4. 当前已经完成的整体流程改造

### 4.1 专家模型库思路已经形成

当前整体应用逻辑已经从“全井统一模型”逐步改为“分地层专家模型库”思路。

统一后的应用逻辑是：

1. 先对目标井按地层切分
2. 在每个地层内部计算目标井与候选成像井之间的属性差异
3. 选择最接近的专家模型
4. 用该专家模型执行第一步裂缝发育段预测
5. 再使用对应第二步细化模型执行点位细化
6. 将各地层结果拼接成整井结果

## 6. 当前还存在的主要问题

### 6.1 第一步仍然是上限约束

当前第二步虽然已经做了较多改进，但最终上限仍明显受第一步制约。

尤其在以下情况下更明显：

- 第一阶段裂缝发育段漏检较多
- 某些地层的第一阶段召回不足
- 跨层井中弱层段的第一阶段预测质量不稳定

如果第一步没有把候选发育段圈出来，第二步无法凭空恢复真实裂缝点位。

### 6.2 沙四段仍明显偏弱

当前分层结果显示：

- 沙三段已经形成相对可用的模型库雏形
- 沙四段整体仍偏弱
- 在跨层井应用时，沙四段往往成为整井结果的短板

### 6.3 第二步仍不能稳定恢复真实条数

虽然当前第二步已经优于早期“逐点密度回归”路线，但仍存在以下问题：

- 某些井段明显欠预测
- 某些井段仍会过预测
- 条数恢复仍不稳定
- `count_error_pct` 在弱井段上仍然偏大

因此当前第二步还不能被解释为“真实裂缝条数恢复器”，更适合解释为“候选裂缝点位细化器”。

### 6.4 整体流程的外部验证还不够

当前已经完成：

- `车151HF` 外层留一验证
- `车660-2` 外层留一验证

但还未完整完成：

- `车662`
- `车663`

因此“专家模型库是否足以支持实际部署”的结论还不能认为最终稳定。

### 6.5 实际部署脚本与当前专家库逻辑仍需继续收口

当前整体流程验证脚本已经支持“分层选模 + 两阶段串联”的验证思路，但用于直接部署的串联脚本仍有待进一步统一到最新逻辑，例如：

- 默认候选井范围仍偏向旧版 4 井设置
- 默认结果目录和默认模型目录仍存在旧版单模型入口
- 需要继续向“按地层自动切分、自动选专家、自动拼接整井结果”的最终部署形式收口

### 6.6 密度与倾向倾角分支尚未真正展开

当前第一部分里：

- 点位细化已经进入主线
- 密度任务已经明确为后续裂缝片大小约束量
- 倾向倾角任务已经明确为后续裂缝片方向约束量

但在代码落地上：

- 密度分支还没有形成稳定独立成果
- 倾向倾角分支尚未真正展开

## 7. 当前阶段性结论

截至 2026-03-25，可以把当前进展概括为以下几点：

1. 项目整体路线已经从“纯模型优化”逐步收敛为“地层约束 + 专家模型库 + 两阶段裂缝预测 + 面向 DFN 的属性表达”。
2. 第一部分中，第一步已经完成从 4 井到 6 井段、从统一模型到分地层模型的重构。
3. 第二步已经从“逐点密度回归”主线转为“发育段门控 + 段级总量标定 + 段内概率分配”主线。
4. 第二步已经形成当前默认的分层混合方案：
   - 沙三段：`sand3_probmass_rule_v1`
   - 沙四段：`sand4_recall_v1`
5. 外层留一整体流程验证已经启动，说明当前专家模型库思路可跑通，但结果仍不足以直接作为最终自动定量成果。
6. 当前更合理的定位是：
   - 第一阶段用于筛选候选裂缝发育段
   - 第二阶段用于给出候选裂缝点位分布趋势
   - 密度用于后续裂缝片尺度约束
   - 倾向倾角用于后续裂缝片方向约束

当前项目已经完成从“单步裂缝识别实验”向“分地层专家模型库驱动的两阶段裂缝预测流程”的转型，但整体能力仍停留在“研究验证和辅助解释”阶段，距离“稳定自动生成 DFN 输入”还有明显差距。
