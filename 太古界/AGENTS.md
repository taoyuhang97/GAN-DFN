# 太古界项目工作约定

本文件是"太古界"目录下的长期工作约定，后续任何人/agent 接手都按此执行。

## 1. 长任务：tmux 后台 + 面板与日志双写

- 预计超过 1 分钟的任务（重跑链条、训练、体预测、剖面出图等）**一律放 tmux 后台**，
  启动后把**会话名 + 日志路径**告知用户，不要在前台盯着。
- **stdout/stderr 必须同时进 tmux 面板和日志文件**：

  ```bash
  # 启动方式（面板可见 = 用户能直接看进度）
  tmux new-session -d -s <会话名> "cd /home/tyh/projects/petroleum/code/GAN-DFN && \
    bash <脚本> 2>&1 | tee <总日志>"

  # 脚本内部每一步同样双写
  $PY <step 脚本> 2>&1 | tee "$LOG/stepN.log" || fail "stepN"
  ```

  理由：只重定向到文件时，tmux 面板长时间空白，看起来像卡死（长步骤每 2 分钟才打一行进度）。
  面板是给人看的实时进度，日志文件是执行完成后的分析依据，两者都要。
- 脚本需带 `set -uo pipefail`，这样 `cmd | tee log || fail` 能正确捕获 cmd 的失败。
- 步骤边界写进总日志（`===== StepN =====` + 时间戳），便于事后算各步耗时。

## 2. 不要修改正在运行中的脚本

bash 是边读边执行脚本文件的；运行期间编辑该脚本会导致后续命令被误读。
需要改脚本时，先等任务结束（或另存为新脚本再启动）。

## 3. 版本与产物管理

- 新口径用新后缀（`v4`/`r4`…），**不覆盖旧产物**，旧配置移入 `configs/_superseded/`，
  不直接删除（本仓库曾因"版本不明"排查过多次）。
- 产物目录（`*/output/`、`output_*_logs/`）按 `.gitignore` 不入库；日志目录体积很小（百 KB 级），
  不为了省空间删日志；真正占空间的是各步旧口径产物，清理放在新版本验收通过之后。

## 4. 文档同步

- 口径决策、实测结果、遗留问题写入 `太古界/太古界流程梳理与问题记录_20260915.md`，
  按 `0.x` 小节追加，编号连续、带日期。
- 对外可照读的流程说明放 `太古界/太古界流程分析记录_20260916.md`。
- 改了某一步的口径，必须同步更新该步目录下的 `README.md`。

## 5. 运行与验收

- 链条入口脚本：`run_v4_chain.sh`（当前正式）、`run_r3_chain.sh`、`run_p0_4_r2_chain.sh`（历史对照）。
- 每一步都有 `*_acceptance_summary.json` / `*_summary.json`，**status=pass 才算通过**；
  重跑后先看这些汇总，再看逐井/逐组明细。
