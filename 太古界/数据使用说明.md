# 太古界常规测井与成像测井数据使用说明

更新时间：2026-09-04

## 1. 目的与范围

本文记录太古界地区“常规测井裂缝预测”数据构造所使用的数据、坐标口径、已确认限制和待核验事项。

当前范围仅覆盖：

- `common`：DLIS 与曲线目录公共工具；
- `step1_strata_contracts`：时间层位、时深和成像解释 TVD 界面合同；
- `step2_well_log_segments`：常规测井 MD/TVD/GR/RD/RS 底板；
- `step3_imaging_groups`：成像连续裂缝密度和裂缝点位监督标签；
- `step4_fracture_prediction`：基于 GR/RD/RS 的裂缝预测。

本文不将不同井、不同解释口径的裂缝密度静默合并为同一个真值。

## 2. 坐标与深度域原则

### 2.1 常规测井

常规测井样点原始深度使用 LAS 中的 `MD`（或 `DEPT`）。其地层归属路径固定为：

```text
LAS MD -> 本井时深曲线 -> TIME -> 时间层位面 -> 时间区间/StrataName
```

规则：

- 只允许使用本井时深文件；
- 缺少本井时深文件的常规井直接排除，不复用其他井时深；
- 时深曲线范围外的 MD 不外推；
- 时深曲线大空缺不跨越插值；
- 常规测井最终用于首版模型的基础字段为 `MD/GR/RD/RS`。

时深文件目录：

```text
/data/shared/project-oil/wx数据/埕岛太古界/时深
```

### 2.2 成像测井

当前所有成像测井井缺少可用时深文件。因此成像测井不能通过时间层位面划分地层，也不能借用常规井时深关系。

成像测井地层归属路径固定为：

```text
成像解释成果中的 TVD 地层界面 -> 成像常规测井 TVD 样点 -> StrataName
```

成像井应从其解释成果中提取实际覆盖段的层位归属及实际出现的 TVD 分界面，并单独保存来源和人工核验状态。解释段全部属于单一地层时，只记录该地层归属，不为未出现的界面补造 TVD 数值。

深度语义（2026-08-12 确认）：成像解释成果（解释段上下界、密度/裂缝点位深度、313 窗口）
一律为 **TVD（真实垂向深度）**；LAS 的 DEPT 为 **MD（沿井测深）**。两者通过每口井的
轨迹（井斜文件 > LAS DEV/AZIM 积分 > 直井回退）逐行转换，Step2 输出同时携带
`MD/TVD/X/Y/TIME`。

### 2.3 井点坐标

坐标统一使用投影坐标：X 为横坐标（Easting，米），Y 为纵坐标（Northing，米），
与 `参与井井头信息.dat` 及层位文件坐标口径一致。

来源说明：

- 常规井坐标来自 `参与井井头信息.dat`（25 口），2026-08-12 确认采用；
- 成像井坐标来自项目成员于 2026-08-12 提供。现有机器可读数据中无成像井坐标

### 3.5 断层 300 m 网格固定原点口径

为与砂砾岩地区断层预处理方法保持一致，太古界断层三维曲线及断层片统一采用
300 m × 300 m 平面网格。该网格使用项目级固定原点，不能在不同脚本或不同区域任务中
根据当前数据的最小 X/Y 临时修改：

```text
origin_x = 658800 m
origin_y = 4231500 m
cell_size = 300 m
```

对应的单元编号规则为：

```text
CellI = floor((X - origin_x) / cell_size)
CellJ = floor((Y - origin_y) / cell_size)
```

按该原点，固定网格覆盖范围为：

```text
X：658800–679800 m，共 70 个单元
Y：4231500–4248000 m，共 55 个单元
```

太古界属性主网格和断层文件的实际范围不能被 300 m 整除，因此最后一行/列允许为
不足 300 m 的边界单元，不得为了整除而裁掉矿区边缘。当前 5 km × 5 km demo 区域
对应大致为 `CellI=5–22、CellJ=23–39`。

该固定原点只用于断层曲线的网格归属、断层片文件索引和后期区域恢复，不改变断层点
本身的 X/Y/Time 坐标。后续按指定区域恢复断层时，先将区域边界换算为 `CellI/CellJ`
范围，再读取相交单元中的断层片；同一断层面依据 `FaultNameRaw` 拼接，`StickID` 仅用于
保留原始抽样线来源和 QC 追溯，`FaultFamily` 仅作可选的上层归类。
所有断层片必须保存固定网格的 `CellI`、`CellJ` 和网格边界信息，确保不同区域任务
之间可以复用同一套断层片库。

### 3.6 断层原始文件及字段说明

原始断层文件为：

```text
/data/shared/project-oil/wx数据/埕岛太古界/断层.dat
```

文件目前没有单独的表头，实际每行由 8 列组成。示例：

```text
INLINE-  2147483647 2147483647  676216.10000 4239224.80000 3015.80000 F01_2 629
```

#### 3.6.1 原始 8 列

| 列序 | 原始列名/示例 | 类型 | 单位 | 含义与使用规则 |
|---:|---|---|---|---|
| 1 | `INLINE-` | 字符串 | 无 | 导出文件中的固定标记，不是实际 Inline 编号；只作为格式标识读取，不参与空间索引、分组或建模。 |
| 2 | `2147483647` | 整数 | 无 | 无效的 Inline/索引占位值（超出正常范围）；所有记录基本相同，不能当作真实 Inline 使用。 |
| 3 | `2147483647` | 整数 | 无 | 无效的 Xline/索引占位值；不能用于道号定位或网格重建。 |
| 4 | `X` | 浮点数 | m | 断层解释点的平面 X 坐标（Easting）。用于空间定位、300 m 网格归属及匹配属性主网格。 |
| 5 | `Y` | 浮点数 | m | 断层解释点的平面 Y 坐标（Northing）。用途与 `X` 相同；坐标口径必须与属性道头和井口坐标一致。 |
| 6 | `Time` | 浮点数 | ms | 断层解释点的地震时间坐标，和层位合同处于同一时间域。保留原始精度，不在读取时擅自改成深度；后续可用于层位窗口标记和三维断层面构造。 |
| 7 | `FaultName` | 字符串 | 无 | 解释成果中的细分断层名称，例如 `F01_2`。必须保留原值（标准化字段名为 `FaultNameRaw`），用于追溯来源和区分断层分支。 |
| 8 | `SourceLine`（原始文件有时记作 `Line`） | 整数/字符串 | 无 | 原始平行解释线编号。同一 `FaultName` 下不同编号是同一断层面的不同抽样线；与 `FaultNameRaw` 组合生成 `StickID`，用于来源追踪和线级 QC，不作为最终三维断层面的聚合键。 |

第 2、3 列的 `2147483647` 是软件导出时的缺省整数（常见的最大 32 位整数），不是
缺失坐标可以拿来替代的数值。若后续文件出现其他占位值或列数变化，应先在输入 QC 中
报警并停止自动建面，不应静默解析。

#### 3.6.2 预处理后的标准化字段

断层预处理不会覆盖原始字段，而是生成一份可供 Step6C/Step7C 使用的标准化点表。主要
字段如下：

| 字段 | 类型/单位 | 生成规则 | 后续用途 |
|---|---|---|---|
| `FaultNameRaw` | 字符串 | 原始第 7 列 | 追溯原始解释名、断层分支筛选和结果检查。 |
| `FaultFamily` | 字符串 | 从名称提取主断层族（如 `F01_2` → `F01`），仅作归并标签 | 后续需要时拼接同一主断层族；不用于替代 `FaultNameRaw`。 |
| `SourceLine` | 整数/字符串 | 原始第 8 列 | 保留平行抽样线来源；同一断层面建模时允许多个 `SourceLine` 共同参与。 |
| `StickID` | 字符串 | `FaultNameRaw + "_" + SourceLine` 的稳定组合键 | 唯一标识一条原始抽样线，用于线级 QC 和点位回溯；不是三维断层面的身份。 |
| `X`、`Y` | 浮点数（m） | 原始第 4、5 列 | 三维曲线/断层面坐标及空间裁剪。 |
| `TimeMs` | 浮点数（ms） | 原始第 6 列重命名 | 三维面构造、层位窗口判断和 Step6C 栅格化。 |
| `CellI`、`CellJ` | 整数 | 按固定原点和 300 m 网格计算 | 定位断层片文件及按区域提取；不能替代原始 X/Y。 |
| `LayerWindowStatus` | 枚举 | 根据层位合同标记点是否落入目标层位窗口 | 后续建模筛选提示；原始点表仍保留窗口外点，不在预处理阶段删除。 |

说明：`TraceIdx` 和 `NearestDistanceM` 不属于正式断层几何结果。断层预处理输出的是三维
断层面及其 300 m 空间片，不是属性地震道；如 Step6C 需要将断层栅格化到属性网格，应在
该步骤根据断层片的 `X/Y` 与属性道头进行匹配，不要把属性道索引提前写入断层点表。

曲线/断层片索引还应记录 `SourcePointCount`、`TriangleCount`、`Area3D`、`StrikeDeg`、
`DipDeg` 等 QC 或几何摘要。这些是由点表计算出的统计量，不应重复写入每个点；详细结果
放在曲线级 QC 表和断层片索引表中即可。

#### 3.6.3 字段使用边界

- 断层几何以 `X/Y/TimeMs` 为准，不能使用第 2、3 列伪 Inline/Xline 重建规则网格。
- 线级 QC 使用 `FaultNameRaw + SourceLine`（即 `StickID`）；三维断层面构造必须按
  `FaultNameRaw` 聚合其下全部 `SourceLine`，不能把每条抽样线分别当成独立断层面。
- 不同 `FaultNameRaw` 之间不得合并三角剖分；`FaultFamily` 仅用于上层归类和后续筛选。
- 属性体的统一空间键是 `TraceIdx`，而不是断层文件中的 `Line` 或伪 Inline/Xline。
- `CellI/CellJ` 只表示 300 m 单元归属；区域恢复时先按单元筛选，再按断层标识拼接。
- 所有原始字段和解析异常必须可追溯，任何无法确认的值进入 QC 报告，不静默填补。
