# 太古界流程分析记录

创建：2026-09-16

## 0. 文档定位

**这份文档要做什么**：把太古界当前的**项目实现**按步骤讲清楚——每一步在逻辑上
"需要什么信息 → 做什么判断和换算 → 产出什么信息"，以及为什么这样做、怎么验证。
面向的读者是以后要听我们讲实现的人，所以正文一律用大白话。

**这份文档不做什么**：

- 不做运行说明（不写"先跑哪个脚本"）；
- 不逐脚本解释作用（只在附录 A 留"单元 → 实现位置"的索引，供查证用）；
- 不替代两份既有文档：
  - 运行与数据合同 → 《太古界Step1-4交接文档》《太古界Step5-9交接文档》《数据使用说明》；
  - 问题清单与修复 → 《太古界流程梳理与问题记录_20260915.md》。

**与砂砾岩那份文档的区别**：砂砾岩《砂砾岩地区DFN构造_20260803.md》是"目录与脚本级"的
交接文档（哪个目录、哪个脚本、怎么执行）。本文档只借用它的**步骤层级划分**，
内容换成"逻辑层面的实现梳理"。

## 1. 流程说明清单（对外讲解用）

> 本节是全文最精简的一版：把每一步的"处理逻辑"用大白话凝练成一段，
> 供对外讲解项目实现时直接照读。详细版在后面的逐步分析里。

**一句话总述**

整个项目分两段。第一段解决"**井上哪里有裂缝**"：用成像测井的解释结果当老师，
学会从常规测井（侧向电阻率、自然伽马）判断裂缝，最终给出矿区内每口常规井的裂缝位置。
第二段解决"**裂缝在空间上怎么分布**"：因为真实井太少，就在真实井旁边按地震网格造"虚拟井"
扩充样本，让模型学会"地震属性长什么样，对应多密的裂缝"，得到三维裂缝密度体；
再分别用曲率、蚂蚁、相干刻画小、中、大尺度裂缝，融合成一个三维裂缝网络；
最后用井上的真实观测校正，并沿井切剖面出图。

**逐步说明（十段，每段对应一个分析单元）**

1. **公共层（common）**：地震体是两百多万条按格子排好的"道"，我们先按曲率的道序给它统一编号，
   再圈出其中 5 公里见方的一小块作为本次演示区。然后把这三种属性各自换算成
   0 到 1 的"有多支持这里有裂缝"的分数（蚂蚁分越高越支持、相干分越低越支持、曲率只看大小不看正负），
   并给每条道算出地层的顶、中、底三个时刻——这样后面的地震采样点才知道自己落在哪个地层里；
   最下层位以下还专门留了 50 毫秒的补充窗。甲方的断层线整理成三维面并按 300 米见方切成小块备用。
   井上的深度点则按"哪一次测井"分别挂坐标，绝不混批。

2. **Step1（层位/时深/深度语义合同）**：要让每个测井深度点知道自己在地下哪一层。
   有本井时深的常规井，先把深度换算成地震时间，再拿平面坐标去三张层位面上找最近点，
   得出该点的顶、中、底时刻，看它落在哪一段里；成像井没有自己的时深文件，所以不走时间这条路，
   直接用解释成果里的垂直深度区间判层。借来的时深只写进表里做时间标注，绝不拿来判地层。

3. **Step2（常规测井段底板）**：一口井可能测过好几次，我们让**每一次测井各自成一份表、谁也不合并**。
   每张表里每个深度点都带着平面坐标、垂直深度和地震时间（斜井用井斜数据换算，直井按垂直算），
   再带上自然伽马、深电阻率、浅电阻率三条曲线，并逐点判断属于哪个地层。
   哪一行三条曲线不齐就标成不能用；哪一段缺得太多就如实记录，不去填补。

4. **Step3（成像监督标签）**：成像测井会给出"这一段地层里裂缝有多密"和"具体哪几个深度上有裂缝"。
   我们把同一口井的几次测井按深度接成一条线，把密度曲线插值到每个测井深度点上，
   再把真实裂缝点贴到最近的深度点上，最后按地层和覆盖范围切成几组。
   每组里每个深度点都带三个信息：连续的密度值（模型的答案）、有没有裂缝的辅标记、
   以及这个点上是否有真实解释点。

5. **Step4（分段预测 + 同井合并）**：我们在成像井上学"电阻率低、伽马异常的地方容易有裂缝"，
   然后拿着这套规律去给每口常规井**每一段测井**分别打分——先判断"这个深度有没有裂缝"，
   再对有裂缝的深度判断"大概有多密"。因为一口井可能测过好几次，
   最后要把几次的结果按深度对齐合并成**一条井级裂缝曲线**，并从这条曲线上挑出一批裂缝点。

6. **Step5（虚拟井与训练样本）**：井太少，学不出"属性长什么样＝裂缝多密"。
   所以我们在每口井旁边按地震网格造出 25 个"虚拟井"；虚拟井的位置变了、地层深度也跟着变，
   就要按它在层内的相对位置重新算时间；然后在那个位置读三种属性的"支持裂缝程度"，
   跟源井对比——越像，说明井上的裂缝结论越能搬过去。搬过去以后，密度值再按证据强弱做一次微调。
   这些虚拟样本的权重被压到真实样本的 1/25，避免"假井淹没真井"。

7. **Step6（多尺度证据体）**：先用井上样本学出一张三维"裂缝密度"体，它主要反映曲率看到的
   小尺度信息；再用蚂蚁体去找成片的中等尺度裂缝带，用相干体去找大尺度的断层——
   甲方给的断层原样保留，属性里明显但没被解释出来的补上。
   最后把中大构造的范围往外扩一圈并逐步衰减，做成一张"影响范围图"。

8. **Step7（多尺度裂缝网络）**：密度体只是一堆数字，我们要把它变成一片片"裂缝"：
   在密度高的地方按概率抽点，每片给一个大小和方向，方向优先参考成像井里真实裂缝的走向；
   中尺度裂缝从蚂蚁体找出的裂缝带里成片取；大尺度断层分成两部分——甲方解释的原样保留，
   属性里推断出来的另外存。最后把所有片子和原始断层放进同一个三维文件，
   用编号区分"哪是算出来的、哪是解释给的"。

9. **Step8（井控校正）**：模型先算出一堆裂缝片，但井上是有真实观测的。
   于是我们把井上预测出的裂缝（密集的点先合成"事件"）、成像井解释出的真实点，都当成约束：
   井附近如果已经有小裂缝片，就把最近的一片挪到观测点旁边并采用观测到的方向；
   附近没有就新造一片。成像井周围一定范围内的裂缝密度会适当调高。
   中尺度、大尺度和甲方给的断层一律不动。

10. **Step9（剖面展示）**：沿着井的轨迹切一张弯的剖面，把蚂蚁体、相干体、曲率、振幅（两种画法）
    分别当底图，再把预测的裂缝片和甲方给的断层画上去——裂缝画成带倾斜方向的线段，
    断层单独标出；井上真实的成像裂缝点也标出来方便对比。全区看一遍、井周看一遍，一共 20 张图。

## 2. 整体结构（已确认）

### 1.1 两个阶段

| 阶段 | 要回答的问题 | 包含步骤 | 产出 |
|---|---|---|---|
| **阶段一：井上裂缝** | 裂缝在**井上**长什么样？ | Step1 → Step2 → Step3 → Step4 | **矿区内可用的常规测井裂缝位置**（井级密度曲线 + 裂缝点） |
| **阶段二：矿区裂缝分布** | 裂缝在**空间上**怎么展布？ | 公共层 → Step5 → Step6 → Step7 → Step8 → Step9 | **裂缝密度体 → 多尺度 DFN → 剖面与验收** |

### 1.2 阶段一逻辑线

```text
Step1  定"深度—地层—地震时间"的对应关系
        常规井：用本井时深把测井深度换算成地震时间，再按时间判断地层
        成像井：没有本井时深，改用解释成果里的垂直深度判断地层
Step2  把每口井每次测井整理成逐行表：每个深度点带坐标、带地震时间、带三条曲线
Step3  把成像解释的"裂缝有多密""裂缝点在哪"变成监督标签
Step4  用同一批次（同一次测井）的数据学"电阻率→裂缝"的规律，
        对常规井逐段预测裂缝，再把同一口井的各段结果合并成井级裂缝曲线与裂缝点
```

### 1.3 阶段二逻辑线

```text
公共层  给每条地震道定"地层窗"（目标地层从哪一刻到哪一刻），
        并把三种属性换算成"有多支持这里有裂缝"的统一分数
Step5   真实井太少 → 在真实井旁边按地震道位置造虚拟井；
        用属性在源井与虚拟位置的相似程度判断"井上的裂缝能不能搬过去"；
        真实井样本 + 通过判断的虚拟井样本 → 构成"地震属性 ↔ 裂缝密度"的训练样本
Step6   用这些样本学出三维裂缝密度体；同时分别提取中尺度裂缝带、大尺度断层、
        以及大构造周边的"损伤带"影响范围
Step7   把密度体和各尺度证据变成一片片裂缝（几何），再融合成一个统一的三维裂缝网络
Step8   用井上的裂缝证据和成像真值，校正井附近的小尺度裂缝片
Step9   沿井切剖面出图，并把"数据对不对、图对不对"逐项验收
```

### 2.2 每个单元的写作结构（八段）

**第 1 段：这一步是干什么的**

- 一句话白话说明（不含术语，不出现脚本名）；
- 角色定位：造合同 / 造标签 / 学规律 / 造空间证据 / 几何化 / 校正 / 展示；
- 一句话说明与砂砾岩做法的关系：**直接借用 / 因数据不同而改造 / 太古界新增**。

**第 2 段：输入（要什么信息）**

用"信息"而不是"文件"来描述：

| 需要的信息 | 来自哪里 | 关键口径（单位/坐标系/深度域或时间域） | 规模量级 |
|---|---|---|---|

外部数据与上游产出要分开标注；规模量级用于判断异常（例如"25 口井""13,117 个深度点"）。

**第 3 段：处理逻辑（重点，全文一半以上篇幅）**

- **3.1 主流程**：拆成有序的小步。每小步固定回答三问：
  1. **做什么**（动作，白话）
  2. **为什么必须做**（不做会怎样）
  3. **判据/参数**（阈值、容差、权重取多少，一句话说来源）
- **3.2 关键判据与阈值表**：

| 判据 | 取值 | 为什么这样定 | 依据 |
|---|---|---|---|

- **3.3 用大白话再过一遍**：3–5 句，让完全不懂的人能复述这段逻辑（对外讲解可直接照读）。

**第 4 段：输出（产出什么信息）**

- 逻辑上产出什么信息、给谁用；
- 哪些是**正式下游输入**，哪些只是 QC/审计附件；
- 数量级、口径（单位、坐标、时间轴）。

**第 5 段：怎么判断这一步做对了**

- 这一步自己会检查什么（要点式，不罗列代码）；
- 区分**硬门槛**（不过就不能往下走）和**提示性检查**（只看趋势）。

**第 6 段：与前后步骤的关系**

- 上游：它需要谁的什么信息；
- 下游：谁需要它的什么信息；
- 如果这一步重跑，影响范围到哪里。

**第 7 段：对外解释要点（是什么 / 不是什么）**

专门写容易被误解的点，例如：

"这里的 TIME 是借用邻井时深得到的临时标注，不是本井真实时深"；
"输出的是属性对裂缝的支持程度（0–1 的证据分数），不是裂缝密度"；
"延伸窗的密度没有真值，是外推，只能低置信使用"。

**第 8 段：已知局限与待确认**

数据限制（井少、无真值、时深待核验）、参数未标定、当前近似做法、
以及需要在对外场合提前说明的口径。

### 2.3 写作约定（硬要求）

1. **大白话优先**：先说人话，再补术语；术语第一次出现必须解释。
2. **区分三类信息**：观测（真测到的）／推断（模型算的）／外推（没有真值、靠规律推的）。
3. **数字带单位与来源**：写"采样间隔 0.125 m（段文件实测）"，不写"采样比较密"。
4. **判据写阈值 + 理由**：写"容差 0.0625 m = 深度采样步长的一半，既能覆盖 0.031 m 的
   段间网格偏移，又不会跨到下一个真实样点"。
5. **不写没有判据的评价**：不出现"效果好""对比明显"；要么给指标，要么写"未验证"。
6. **不确定的写进第 8 段**，不用"应该/大概"在正文里糊过去。
7. **不写脚本名**：正文只讲逻辑；实现位置统一放附录 A。

### 2.4 术语对照表（对外讲解可直接照读）

| 术语 | 大白话解释 |
|---|---|
| MD | 沿井筒量出来的深度（井斜了，MD 会比垂直深度长） |
| TVD | 垂直深度（从地面垂直向下量的深度） |
| TIME / TWT | 地震波往返一次的时间（毫秒）；地震数据用时间不用深度 |
| 地震道 / TraceIdx | 三维地震可以看成很多条"道"排成的网格；TraceIdx 就是道的编号 |
| 测井段 / 批次 | 一次测井作业得到的连续数据；同一口井可能测过多次 |
| 三属性 | 相干（地层连不连续）、蚂蚁（追踪断裂痕迹）、曲率（地层弯曲程度） |
| 证据分数 | 把属性值换算成 0–1 的"有多支持这里有裂缝"，不是裂缝密度本身 |
| 连续性 | 源井位置与虚拟位置的属性像不像；越像，标签越能搬过去 |
| 双标签 | 两个标签：有没有裂缝（存在性）＋有裂缝时有多密（条件密度） |
| 虚拟井 | 在真实井旁边按地震道位置造出来的"假井"，用来扩充样本 |
| 主窗 / 延伸窗 | 主窗＝三个层位围出的目标地层；延伸窗＝最下层位以下最多 50 ms |
| 损伤带 | 大裂缝/断层附近受影响的"晕圈"范围 |
| DFN | 离散裂缝网络：用一片片裂缝几何拼出来的三维裂缝模型 |
| 井控 | 用井上的真实裂缝证据去校正模型预测的裂缝片 |
| 原始断层 / 预测裂缝片 | 甲方给的断层解释（原始）vs 模型算出的裂缝片（预测），文件中分组保存 |
| 借用时深 | 成像井没有本井时深，临时借用最近常规井的时深，只用于时间标注 |
| FVDC / P10 / P33 | 成像解释的密度口径；P10＝每米条数，P33＝体积密度 |

### U1 公共层（common）

#### 1. 这一步是干什么的

公共层不产出任何地质结论，它只做四件"打地基"的事：

1. 给三种地震属性定一套**共用的道号和坐标**（哪条道在哪儿）；
2. 划出本次工作的范围（5×5 km 演示区）并列出范围内的道；
3. 把属性值翻译成统一的"**有多支持这里有裂缝**"的分数（0–1）；
4. 给每条地震道算出目标地层的**顶/中/底时刻**和层段窗口。

另外附两件支撑：把甲方的断层解释整理成"面片库"，以及"把井上深度点接到具体测井段"的公共工具。

**角色定位**：提供所有步骤共用的空间与证据基准（造合同）。

**与砂砾岩的关系**：**因数据不同而改造**——砂砾岩用 T4–T7 四界面 + 一套 psdm 网格；
太古界是三个界面 + 属性主网格，且原始振幅退出建模。断层 300 m 网格与统一 VTK 属于**直接借用**。

#### 2. 输入（要什么信息）

| 需要的信息 | 来自哪里 | 关键口径 | 规模量级 |
|---|---|---|---|
| 三种属性体（相干 / 蚂蚁 / 最大正曲率） | 外部体数据目录（SEG-Y） | IEEE float，1 ms，3,001 样；文件内时间 = 索引 + 1800 ms | 各 2,156,550 道 |
| 三个层位面（上部复合层顶 / 太古界顶 / 风化壳底） | 外部层位目录（文本） | 每行 inline、xline、X、Y、时间(ms) | 顶部面约 190 万行 |
| 断层线段解释 | 外部 `断层.dat` | 8 列：X(m)、Y(m)、时间(ms)、断层名、线号等 | 5,246 行 / 93 个断层名 / 1,067 条线 |
| OBN 振幅体道头 | 外部 OBN SEG-Y | 12.5 m 网格，1 ms，7,001 样 | 2,002,838 道 |
| 演示区范围与网格 | 项目配置 | X 范围、Y 范围、12.5 m 间距 | 401×401 |

#### 3. 处理逻辑（重点）

##### 3.1 主流程（八个小步）

**(a) 统一属性道号**

- 做什么：以**曲率体**的道序作为唯一主道号，把相干体、蚂蚁体按同一道号对齐。
- 为什么必须做：三种属性必须能"用同一个编号读同一位置"，否则没法联合判断；不做就会出现
  "相干读的是 A 位置、曲率读的是 B 位置"。
- 判据/参数：三体道数都必须是 2,156,550；相干与曲率逐道坐标偏差为 0；蚂蚁与曲率最大偏差 ≤
  1.414 m（米级取整造成），中位 1 m。

**(b) 圈定演示区**

- 做什么：在属性主网格上切出 X 660500–665500、Y 4238400–4243400 的 5×5 km 方块，
  12.5 m 间距 → 401×401 = 160,801 条道，并记录每条 demo 道对应的主网格道号。
- 为什么必须做：全网格 215 万道，整块跑代价过大；先在一个方块里把方法跑通。
- 判据/参数：demo 道到属性主网格道的匹配距离 ≤ 2 m；实测最大 1.414 m、中位 1 m，且一一对应。

**(c) 属性 → 裂缝证据分数**

- 做什么：把三种属性各换算成 0–1 的"证据分数"，并按地层分别定标。
  - 蚂蚁：原始值越大分越高（`-1` 是"弱/无裂缝"的有效响应，不是缺测）；
  - 相干：原始值越低分越高（低相干＝地层不连续＝裂缝证据）；
  - 曲率：先取**绝对值**，再按"异常越大分越高"。
- 为什么必须做：三种属性的量纲、正负方向都不同，不换算成同一尺度就无法按权重融合；
  曲率不取绝对值，会把"负曲率异常"错当成"低裂缝证据"。
- 判据/参数：按地层（上部复合层 / 风化壳）分别取 2%–98% 稳健分位数定标；
  原始值保留，不覆盖。

**(d) 逐道层位合同**

- 做什么：给每一条属性道，从三个层位面上取最近的解释点，得到该道的顶/中/底三个时刻；
  再检查三者顺序（顶 < 中 < 底），顺序不成立的标为无效。
- 为什么必须做：后面所有"这个点算不算在目标地层里"的判断都靠它；不做就只能用固定时间范围，
  遇到地层起伏就会把非目标层当成目标层。
- 判据/参数：层序必须单调；无效道标记 `SurfaceValid=0`，下游读到无效即不参与计算。

**(e) 层窗索引（把时刻变成数组下标）**

- 做什么：把每一条道的顶/中/底时刻换算成 2 ms 采样轴上的起止下标，并分别标记
  "上部复合层 / 风化壳 / 最下层位以下 50 ms 的延伸窗"是否存在。
- 为什么必须做：体数据是数组，用下标取值比每次查时间更快、更不容易出错。
- 判据/参数：2 ms 轴范围 1958–4758 ms，共 1,401 样；延伸窗固定 50 ms。

**(f) 断层片库**

- 做什么：把断层线段按"断层名"聚合成三维面，再按 **300 m 固定网格**切片存库。
- 为什么必须做：大尺度裂缝几何需要"面"而不是"线"；固定网格保证不同区域任务能复用同一套片库。
- 判据/参数：网格原点固定 (658800, 4231500)，单元 300 m；单片最大三角边长 500 m；
  产出 4,494 个片。

**(g) 逐段回接工具**

- 做什么：把"某个井上深度点"接到**它所属的那一次测井段**上，取到该点的坐标与地震时间；
  匹配不上时记录原因，不静默丢弃。
- 为什么必须做：一口井可能测过多次，段与段之间还有重叠；不明确"这个点属于哪一批"，
  就会把不同批次的数据混在一起。
- 判据/参数：只在"该行自己所属的段"内匹配（不跨段、不平均）；容差取该段深度采样步长的一半
  （实测 0.0625 m 量级），既覆盖段间网格偏移、又不会跨到下一个真实样点。

**(h) OBN 对照与振幅采样**

- 做什么：记录 OBN 振幅网格与属性网格的覆盖差异，并提供按道读振幅的工具。
- 为什么必须做：振幅与属性网格不是同一套（道数 200.3 万 vs 215.7 万），
  必须让所有人知道"哪里有、哪里没有"，避免把缺道当成"没有裂缝"。
- 判据/参数：以 2 m 容差判定"附近有邻道"；实测约 21 万条属性道附近没有 OBN 道、
  约 5.6 万条 OBN 道附近没有属性道；振幅**只用于剖面背景展示**。

##### 3.3 用大白话再过一遍

> 地震体是一大堆按格子排好的"道"，一共 215 万条。我们先按曲率的道序给它们统一编号，
> 再圈出其中 5 公里见方的一小块（16 万条道）作为本次演示区。接着把相干、蚂蚁、曲率三种属性
> 各换算成 0 到 1 的"支持裂缝程度"分数——蚂蚁分越高越支持、相干分越低越支持、
> 曲率只看大小不看正负。然后给每条道算出目标地层的顶、中、底三个时刻，
> 这样后面的地震采样点才知道自己落在哪个地层里；最下层位以下还留了 50 毫秒的补充窗。
> 甲方的断层线整理成三维面、按 300 米见方切成小块备用。
> 井上的数据则按"哪一次测井"分别挂坐标，绝不混批。

#### 5. 怎么判断这一步做对了

**硬门槛**（不过就不能往下走）：

1. 三属性道数一致，且相干/曲率逐道坐标一致；
2. 演示区每条道都能在属性主网格里找到唯一对应道（≤2 m）；
3. 有效道的层序满足 顶 < 中 < 底，且层窗非空；
4. 层窗索引与采样轴严格对应（2 ms、1,401 样）。

**提示性检查**：全区层位覆盖率、OBN 与属性的覆盖差异、断层片的数量与几何 QC。

**当前需要注意的一点**：全区层位合同的自动验收是 **fail**——因为它在**全网格**上要求覆盖率 ≥99%，
实测只有 **87.78%**（层位解释的覆盖范围本来就小于属性体）。下游只用演示区子集（覆盖率 99.61%）
所以暂时没有影响，但**将来扩到全矿区时必须先解决层位覆盖**。

#### 6. 与前后步骤的关系

- **上游**：全部来自外部数据（三属性体、三个层位面、断层线段、OBN 道头）与项目配置。
- **下游**：Step5（演示区道 + 属性分数 + 层位）、Step6A/6B/6C（层位与证据分数）、
  Step7（层位、断层片、几何工具）、Step8/9（层位、回接工具、OBN 背景）。
- **重跑影响范围**：属性主道号或层位合同一旦变化，Step5 及其后**全部**步骤都要重跑；
  只改 OBN 对照或展示用振幅，则不影响建模链。

#### 7. 对外解释要点（是什么 / 不是什么）

1. **"属性主网格"不是 OBN 网格**：前者 215.7 万道、以曲率道序编号；后者 200.3 万道。
   OBN 振幅只用于剖面背景，不参与裂缝建模。
2. **"证据分数"不是裂缝密度**：它只回答"这个位置有多支持有裂缝"（0–1），
   密度要靠 Step6 的模型算。
3. **这里的层位合同是"逐地震道"的**，与 Step1 的"逐井点"层位合同是两套东西，不能互换。
4. **延伸窗（最下层位以下 50 ms）没有真值**，属于外推，只能低置信使用。
5. **演示区里的 623 条道层位无效**：它们不参与任何计算，不是"没有裂缝"。
6. **蚂蚁体的 `-1` 不是缺测**，而是"弱/无裂缝"的有效响应。

### U2 Step1 层位 / 时深 / TVD 合同

#### 1. 这一步是干什么的

给每口井建立"深度—地层—地震时间"的对应关系：**某个测井深度属于哪个地层、对应什么地震时间**。
它不产裂缝，只产合同，是阶段一的起步。

**角色定位**：造合同。

**与砂砾岩的关系**：**因数据不同而改造**。砂砾岩 Step1 是"给任意点样本挂 T4–T7"；
太古界把同一件事拆成两条路径，因为**成像井没有本井时深**，不能用时间判地层。

#### 2. 输入（要什么信息）

| 需要的信息 | 来自哪里 | 关键口径 | 规模量级 |
|---|---|---|---|
| 井点与井底坐标 | 外部井头文件 | X/Y（米）、补心海拔、井底坐标 | 25 口常规井 |
| 时深关系 | 外部时深文件 | TIME / TVDSS / TVD / MD | 按井分布 |
| 三个层位面 | 外部层位目录 | inline、xline、X、Y、时间(ms) | 顶部面约 190 万行 |
| 常规测井曲线清单 | 外部常规测井目录 | 只看曲线名是否存在 | 25 口井的匹配情况 |
| 成像解释段深度区间 | 配置内人工登记 | 解释段 TVD 区间 + 人工分界面 | 8 口成像井 |

#### 3. 处理逻辑（重点）

##### 3.1 主流程（五个小步）

**(a) 判断井型**

- 做什么：比较井口与井底的横向偏移，偏移 ≤5 m 视为直井。
- 为什么必须做：斜井的"沿井深度"与"垂直深度"差别很大，必须区分才能正确换算。
- 判据/参数：横向偏移 ≤5 m → 直井（后续用垂直回退：垂直深度＝沿井深度、坐标取井口）。

**(b) 常规井走"时间路径"**

- 做什么：用**本井时深**把每个测井深度换算成地震时间；再用该点的 X/Y 去三个层位面上找最近点，
  得到该点的顶、中、底三个时刻；最后按时刻落在哪个区间判断地层：
  顶≤时间<中 → 上部复合层；中≤时间<底 → 太古界风化壳。
- 为什么必须做：只有把测井深度换算到地震时间域，才能和地震数据对齐；
  地层归属必须逐点判断，因为层位面是起伏的。
- 判据/参数：**只允许用本井时深**（禁止借用他井）；井点到层面最近距离 ≤100 m；
  层序必须满足 顶<中<底；时深关系必须单调。

**(c) 成像井走"垂直深度路径"**

- 做什么：不使用时深。直接用成像解释成果里的**垂直深度区间**判断地层；
  对埕北305、埕北313 这两口跨地层的井，用人工确认的分界面切分。
- 为什么必须做：成像井没有本井时深，若强行用借来的时深判地层，很可能把解释段判到地层之外
  （实测确实会把深部解释段映射到最下层位以下）。
- 判据/参数：埕北305 → 垂直深度 4221 m；埕北313 → 垂直深度 4783 m；
  单地层井整段归属该地层。

**(d) 借用时深只做标注**

- 做什么：给成像井的深度点也写一个地震时间，但明确标记"这是借来的"。
- 为什么必须做：后续展示和剖面要用到时间；但借用的时深不能用来判地层。
- 判据/参数：所有借用点打 `temporary_neighbor_time_depth` 标记；**不参与层位门控**。

**(e) 记录"合同齐备"与"曲线是否有目标段"**

- 做什么：先看曲线名是否齐（给出"合同有效"），再记录时深覆盖是否进入目标时间区间。
- 为什么必须做：两者是不同的事——有曲线名不等于有目标段数据；混在一起会误判可用井数。
- 判据/参数：20 口合同有效、5 口缺常规测井；**14 口的时深覆盖未进入目标时间区间**。

##### 3.2 关键判据与阈值表

| 判据 | 取值 | 为什么这样定 | 依据 |
|---|---|---|---|
| 直井判定 | 顶底横向偏移 ≤5 m | 偏移极小说明井近似垂直，可用垂直回退 | 决策记录（2026-08-12） |
| 井点到层面距离 | ≤100 m | 层位解释是散点，需要容差；实测 25 口井最大 7.767 m | 实测 |
| 层序有效 | 顶 < 中 < 底 | 顺序倒置说明层位解释有问题，不能用于判层 | 合同校验 |
| 时深单调 | 必须单调递增 | 不单调则时间换算不可信 | 合同校验 |
| 地层区间 | 顶≤T<中 / 中≤T<底 | 与砂砾岩的分层语义一致（界面口径统一） | 数据使用说明 §4 |
| 时深使用 | 只用本井时深 | 借用的时深关系不可信 | 数据使用说明 §8 |
| 借用时深用途 | 仅 TIME 标注，不做层位门控 | 借用关系可能把解释段映射到目标层之外 | 数据使用说明 §2.4 |

##### 3.3 用大白话再过一遍

> 我们要让每个测井深度点知道自己"在地下哪一层"。有本井时深的常规井，就先把深度换算成
> 地震时间，再拿它的平面坐标去三张层位面上找最近点，得出该点的地层顶、中、底三个时刻，
> 看它落在哪一段里。成像井没有自己的时深文件，所以不走时间这条路，直接用它解释成果里的
> 垂直深度区间判层。借来的时深只写进表里做时间标注，绝不拿来判地层。

#### 4. 输出（产出什么信息）

| 产出 | 内容 | 给谁用 |
|---|---|---|
| 常规井合同（25 行） | 井点三界面时刻、最近距离、层序/时深校验、合同状态 | Step2 |
| 点级 MD-TIME 记录（13,117 行） | 每个深度点的时间与地层分类；其中 491 行落在目标层内（上部复合层 399 / 风化壳 92） | Step2 裁剪依据 |
| 成像井垂直深度合同（8 行） | 解释段区间、分界面、来源、合同状态 | Step2 / Step3 |
| 点级清单与验收 summary | QC 附件 | 审计 |

#### 5. 怎么判断这一步做对了

- **硬门槛**：层序有效（顶<中<底）、时深单调、井点到层面距离在容差内；
- **提示性**：合同有效井数（20/25）、有目标段井数（11）、成像井合同齐备（8/8）；
- **当前状态**：25 口常规井中 20 口合同有效、5 口缺常规测井；按目标层裁剪后只剩 491 个
  深度点落在目标层内——这不是报错，而是"时深覆盖本来就够不到目标地层"。

#### 6. 与前后步骤的关系

- **上游**：全部来自外部数据（井头、时深、层位、测井目录）与配置中的人工登记。
- **下游**：Step2 按合同裁剪常规井、按垂直深度合同裁剪成像井；Step3 用成像井的垂直深度合同。
- **重跑影响**：层位、时深或井坐标一旦变化，Step2 及其后**全部**步骤都要重建。

#### 7. 对外解释要点（是什么 / 不是什么）

1. **成像井的"地层归属"不是从测井曲线算出来的**，而是来自解释成果 + 人工确认的分界面，
   属于强假设。
2. **借用的时深不是本井真实时深**，只用于时间标注。
3. **"合同有效"不等于"有目标段数据"**：25 口里 14 口的时深覆盖够不到目标地层。
4. **单地层井的"整段归属"不等于整条测井曲线都属于该地层**：只表示解释段范围内如此。
5. **这里的层位合同是"逐井点"的**，与公共层那套"逐地震道"合同不是一回事。

#### 8. 已知局限与待确认

| 项 | 说明 |
|---|---|
| 地层命名 | "上部复合层 / 太古界风化壳"是项目内部命名，需与地质认识对齐 |
| 层位匹配阈值 | 100 m 偏松（实测最大 7.767 m），新增井需复检 |
| 成像井分界面 | 305 / 313 的分界面是人工确认值，来源与核验状态未登记 |
| 成像井坐标 | 由项目成员提供，未用井口文件交叉核验 |
| 可用井数 | 14 口常规井够不到目标地层，直接限制阶段一的训练井数 |

### U3 Step2 常规测井段底板

#### 1. 这一步是干什么的

把每口井**每一次测井**整理成一张"逐行表"：每一行是一个深度点，带着它的平面坐标、
垂直深度、地震时间，以及这一行的三条曲线值（自然伽马、深电阻率、浅电阻率）。
同一口井测过多次时，**每次测井各自成段、重叠部分都保留**。

**角色定位**：造阶段一的逐行数据底板。

**与砂砾岩的关系**：**因数据不同而改造**。砂砾岩每口井整理成**一张**主表（多文件按覆盖
与采样密度"择一"补齐，不取平均）；太古界刻意**不在这里选源**，而是把每次测井独立成段、
把"选谁"推迟到预测之后合并阶段。

#### 2. 输入（要什么信息）

| 需要的信息 | 来自哪里 | 关键口径 | 规模量级 |
|---|---|---|---|
| 井-地层-时间合同 | U2（Step1） | 逐井点或逐段的地层归属 | 25 常规 + 8 成像 |
| 常规测井曲线 | 外部 LAS | 深度＝沿井深度（MD）；GR/RD/RS | 25 口井目录 |
| 成像井测井曲线 | 外部 LAS | 同上 | 8 口井目录 |
| 井斜轨迹 | 外部井斜文件 | MD→TVD/X/Y | 12 口常规井 |
| 时深关系 | 外部时深文件 | MD↔TIME | 按井分布 |
| 层位面 | 外部层位目录 | 用于逐行判层 | 三个界面 |

#### 3. 处理逻辑（重点）

##### 3.1 主流程（七个小步）

**(a) 一个 LAS 来源 = 一个段**

- 做什么：每个测井文件（必要时按覆盖中断再拆）单独输出一个段文件，绝不合并。
- 为什么必须做：不同测次是不同批次的观测，合并会让"段内连续"这一前提失效；
  保留段身份，后面才能按批次分别建模、最后再合并。
- 判据/参数：段文件命名带段号；段清单逐段登记来源、测年、曲线列、深度范围。

**(b) 选曲线列**

- 做什么：自然伽马按 `GR > GR1 > GRSL` 优先级取一条；深、浅电阻率固定取 `RD`、`RS`。
- 为什么必须做：外部 LAS 里同一物理量的列名可能有好几种，不统一就无法跨井建模。
- 判据/参数：实际用到的列名写进段清单，便于回溯。

**(c) 逐行建立轨迹（沿井深度 → 垂直深度与平面坐标）**

- 做什么：给每一行算出垂直深度和平面坐标，来源按优先级：**井斜文件 → LAS 自身的
  井斜/方位曲线积分 → 直井回退**（垂直深度＝沿井深度、坐标＝井口）。
- 为什么必须做：测井深度是"沿井筒"量出来的，地震与层位用的是"垂直深度 + 平面坐标"，
  不换算就对不上；斜井不换算会差出几十到几百米。
- 判据/参数：直井判定用 U2 的 5 m 规则；轨迹来源逐段登记。

**(d) 逐行判地层**

- 做什么：常规井用**每一行自己的平面坐标**去查三个层位面，判断属于哪一层；
  成像井按 U2 的垂直深度合同判断。
- 为什么必须做：同一口井不同深度可能落在不同地层，按井整体判层会错。
- 判据/参数：常规井走逐行坐标；成像井走垂直深度区间。

**(e) 记录"这一行能不能用"**

- 做什么：逐行检查三条曲线是否同时有效；逐段统计"原始行数"与"完整行占比"。
- 为什么必须做：模型只接受三条曲线同时有效的行；不统计就不知道某口井到底有多少可用数据。
- 判据/参数：完整占比写入段清单，作为选井与诊断依据；不完整的行不补零、不外推。

**(f) 成像井的时间标注**

- 做什么：成像井借用最近常规井的时深，把深度换算成时间，并打"借用"标记。
- 为什么必须做：剖面与展示需要时间；但借用关系不可信，必须让下游知道。
- 判据/参数：按"该常规井时深能完整覆盖解释段"的前提选择借用井（如埕北305 借 CB39）。

**(g) 尊重人工给定的硬窗口**

- 做什么：对个别井按人工确认的垂直深度窗口裁剪，中间断口不拼接。
- 为什么必须做：例如埕北313 的解释段被分成 4174–4627 m 与 4751–4884 m 两段，
  中间是没有解释的区间，拼起来会凭空造出连续段。
- 判据/参数：窗口写在配置里，作为硬约束。

##### 3.2 关键判据与阈值表

| 判据 | 取值 | 为什么这样定 | 依据 |
|---|---|---|---|
| 一个 LAS 一个段 | 不合并 | 保证"段内是同一批次连续观测" | 设计决策 |
| 曲线优先级 | GR > GR1 > GRSL；RD/RS 固定 | 统一曲线口径 | 实现约定 |
| 轨迹优先级 | 井斜文件 > LAS 曲线积分 > 直井回退 | 优先用最可靠的轨迹来源 | 实现约定 |
| 直井回退条件 | 顶底横向偏移 ≤5 m | 近似垂直，可安全回退 | U2 决策 |
| 完整行定义 | 三条曲线同时有效 | 模型要求三特征齐备 | Step4 特征合同 |
| 无效值 | 明确负值（如 -999.25）转缺失 | 不能当真实低值参与计算 | 数据使用说明 §5.3 |
| 缺口处理 | 不跨越明显大空缺插值 | 避免造出不存在的数据 | 数据使用说明 §5.3 |
| 人工窗口 | 按井写死，断口不拼 | 尊重解释成果的实际覆盖 | 配置 |

##### 3.3 用大白话再过一遍

> 一口井可能测过好几次，我们让每一次测井各自成一份数据表，谁也不合并。
> 每张表里，每个深度点都带上它的平面坐标、垂直深度和地震时间（斜井要用井斜数据换算，
> 直井就按垂直算），再带上自然伽马、深电阻率、浅电阻率三条曲线。
> 然后逐点判断这个深度属于上部复合层还是风化壳。哪一行三条曲线不齐，就标成不能用；
> 哪一段缺得太多，就如实记录，不去填补。

#### 4. 输出（产出什么信息）

| 产出 | 内容 | 给谁用 |
|---|---|---|
| 段文件（29 段 / 17 井） | 逐行：沿井深度、垂直深度、X/Y、地震时间、地层、三条曲线 | Step3、Step4 |
| 段清单（29 行 × 29 列） | 每段的来源、测年、曲线列、深度范围、行数、完整占比、轨迹/时深来源、借用井 | 选井与审计 |
| 井元数据 | 井坐标、层位界面、轨迹与时深来源、状态 | Step5 等 |
| 放弃井表（16 口） | 放弃原因 | 审计 |
| 验收 summary | — | 审计 |

#### 5. 怎么判断这一步做对了

- **硬门槛**：段清单与段文件一一对应、逐行坐标/时间/地层齐备、曲线列登记完整；
- **提示性**：每段完整行占比、轨迹来源分布；
- **当前结果**：33 口配置井 → **17 口可用**（10 常规 + 7 成像）、29 个段、53,394 行；
  16 口放弃（5 口缺常规测井、11 口没有目标段）。段数分布：8 口井 1 段、6 口井 2 段、3 口井 3 段。

#### 6. 与前后步骤的关系

- **上游**：U2 的合同、外部测井/井斜/时深/层位。
- **下游**：Step3 用段文件承载监督标签；Step4 **直接读段文件**逐段预测；
  Step5 的强监督回接、Step8/9 的坐标回接都要用到段文件。
- **重跑影响**：段文件一旦变化（新增测井、轨迹或时深修正），Step3 之后全部要重建。

#### 7. 对外解释要点（是什么 / 不是什么）

1. **"段"就是一次测井作业**，同一口井可能有好几段，段与段之间可能重叠也可能有缺口。
2. **段之间不做合并、average 或插值**——这是刻意设计，保证每一段内部的规律一致。
3. **成像井的地震时间是借来的**，只用于标注。
4. **曲线不齐的深度不补零**：这类行直接标为不可用。

#### 8. 已知局限与待确认

| 项 | 说明 |
|---|---|
| 段间治理留给了下游 | 重叠区会出现"同深度多个批次"的行，合并规则在 Step4（当前为等权平均，待标定） |
| 成像井坐标未核验 | 井口坐标由项目成员提供，未与井口文件交叉验证 |
| 借用时深的覆盖前提 | 按"借用井时深能覆盖解释段"选取，但借用的时间值本身不可信 |
| 放弃井 | 16 口放弃是数据现实（缺曲线 / 无目标段），不是实现缺陷 |

### U4 Step3 成像监督组

#### 1. 这一步是干什么的

把成像测井解释成果里的两样东西——**连续的裂缝密度曲线**和**真实的裂缝点位**——
变成能跟测井行一一对齐的监督标签，供第 4 步学习"电阻率→裂缝"的规律。

**角色定位**：造监督标签（阶段一里唯一的"真值"来源）。

**与砂砾岩的关系**：**因数据不同而改造**。砂砾岩的成像监督来自若干固定井段的
手工区间；太古界的成像解释成果分散在多个文件、密度列名和统计范围各不相同，
因此新增了"逐井登记密度来源与点位来源"的做法。

#### 2. 输入（要什么信息）

| 需要的信息 | 来自哪里 | 关键口径 | 规模量级 |
|---|---|---|---|
| 段文件与段清单 | U3（Step2） | 逐行深度、垂直深度、坐标、时间 | 29 段 |
| 成像裂缝密度 | 外部成像解释文件 | 各井不同列名（FVDC / VDC01 / P10_SUM_C / P10_SUM_裂缝密度 / FVDC(P10)） | 6 口井有密度 |
| 成像裂缝点位 | 外部成像解释文件 | 点位深度 + 方位/倾角 | 6 口井有点位 |
| 逐井配置 | 项目配置 | 指定每口井用哪个密度列、哪个点位文件 | 8 口成像井 |

#### 3. 处理逻辑（重点）

##### 3.1 主流程（五个小步）

**(a) 把一口井的段拼成一条"按垂直深度排序"的表**

- 做什么：把该井所有段文件上下拼起来，按垂直深度排序，但**保留每一行属于哪个段**。
- 为什么必须做：成像密度只按深度给出，需要一条完整的深度轴才能插值；
  保留段身份，是为了让后面的标签仍然能追溯到具体测次。
- 判据/参数：不删重复深度（重叠区同深度会有多行），只排序。

**(b) 把连续密度插值到这条深度轴上**

- 做什么：按垂直深度把成像密度插值到每个测井行。
- 为什么必须做：成像解释的采样间隔与测井不同，必须对齐到同一深度轴才能当标签。
- 判据/参数：**只在原始密度有效覆盖范围内插值**；两端间隔超过阈值就不插（留空）；
  密度为 0 是有效标签，缺测/超范围必须是空值。

**(c) 把真实裂缝点吸附到最近的测井行**

- 做什么：把成像解释的真实裂缝点按深度吸附到最近的行，并打点标记；
  同一个位置有多个点时，把方位、倾角合并。
- 为什么必须做：这些点是"确定有裂缝"的证据，用于构造模型的正样本与点位级验证。
- 判据/参数：吸附必须在容差内；超出容差的点记为未映射，不强行贴上去。

**(d) 切分成"监督组"**

- 做什么：按地层变化或密度覆盖的断口，把该井的表切成若干组。
- 为什么必须做：一个组对应一段连续、可比的标签区间；跨断口拼在一个组里会让统计失真。
- 判据/参数：切分依据是"地层变化"或"密度覆盖中断"。

**(e) 固化标签语义**

- 做什么：输出固定 18 列，明确三种标签的关系与状态字段。
- 为什么必须做：下游要靠这些字段区分"连续密度""二值有无""真实点位"三种不同信息。
- 判据/参数：`Density` 连续主标签；`HasFractureDensity` 只是 `Density>0` 的辅助；
  `GT_POINT_FLAG` 表示真实解释点；另有 `DensityKind`/`FractureScope` 记录密度口径与统计范围。

##### 3.2 关键判据与阈值表

| 判据 | 取值 | 为什么这样定 | 依据 |
|---|---|---|---|
| 密度插值范围 | 只在原始覆盖范围内 | 范围外是外推，没有依据 | 数据使用说明 §6 |
| 插值最大间隔 | 按井配置（避免跨大空缺） | 跨大空缺插值会造出不存在的密度 | 配置 |
| 点位吸附 | 必须在容差内 | 超容差说明点位与测井深度对不上 | 配置 |
| 密度为空 | 缺测/覆盖外 → 空值 | 不能把"没测到"当成"没有裂缝" | 数据使用说明 §8 |
| 密度为零 | 有效标签 | 零是"测到了、没有裂缝" | 数据使用说明 §6 |
| 标签分工 | 密度 / 二值 / 真实点 三者分开 | 三者语义不同，不能互相替代 | 设计决策 |

##### 3.3 用大白话再过一遍

> 成像测井会给出"这一段地层里裂缝有多密"和"具体哪几个深度上有裂缝"。
> 我们把同一口井的几次测井按深度接成一条线，把密度曲线插值到每个测井深度点上，
> 再把真实裂缝点贴到最近的深度点上。最后按地层和覆盖范围切成几组，
> 每组里的每一个深度点都有：一个连续的密度值（这就是模型的答案）、
> 一个"有没有裂缝"的辅标记、以及"这个点上是否有真实解释点"的标记。

#### 4. 输出（产出什么信息）

| 产出 | 内容 | 给谁用 |
|---|---|---|
| 监督组 CSV（8 组 / 6 井 / 28,751 行） | 固定 18 列：组号、井名、来源段、深度、垂直深度、地层、密度、辅标记、真实点标记、方位/倾角、口径与状态 | **Step4 训练的唯一监督输入** |
| 组清单 | 每组深度范围、行数、正样本数、真实点数、属性有效数 | 审计与选井 |
| 来源清单 | 每组用到的密度/点位/底板文件路径 | 追溯 |
| 点位映射 QC、逐井放行 QC、交付验收 | 点位账目、逐井豁免、合同检查（`status=pass`） | 审计 |

#### 5. 怎么判断这一步做对了

- **硬门槛**：列合同与约定完全一致；`Density` 非空；`HasFractureDensity` 严格等于 `Density>0`；
  真实点标记只能取 0/1；点位的"映射 + 未映射"账目闭合；被上游放弃的井豁免检查；
- **当前结果**：8 个组、6 口井、28,751 行，交付验收 `status=pass`；
  其中埕北古斜405 一组 5,903 行、真实点位 316 个。

#### 6. 与前后步骤的关系

- **上游**：U3 的段文件与段清单、外部成像解释成果。
- **下游**：Step4 用它训练两个地层专家；Step8 用**埕北古斜405 这一组**当井控真实证据。
- **重跑影响**：标签或点位一旦变化，Step4 必须重训、其后全部重建。

#### 7. 对外解释要点（是什么 / 不是什么）

1. **`GT_POINT_FLAG=1` 是"真实的解释点位"，不等于 `Density>0`**：密度是连续量，
   点位是离散观测。
2. **不同井的密度列名与统计范围不同**（FVDC / VDC01 / P10_SUM_C / P10_SUM_裂缝密度 /
   FVDC(P10)），当前按甲方口径直接使用，不做跨井换算。
3. **重叠测次会让同一深度出现多行**，这些行标签相同、曲线不同。
4. **空值不是零**：没测到的地方保持空，不能被当作"没有裂缝"。

#### 8. 已知局限与待确认

| 项 | 说明 |
|---|---|
| 密度口径不统一 | 各井统计范围不同（是否含低角度裂缝等），当前按甲方口径使用，不做换算 |
| 强监督井少 | 只有 6 口井有监督；风化壳层的强监督仅 2 口（埕北313、埕北816） |
| 重叠测次的重复行 | 同一深度可能有多行（不同批次），其权重处理在 Step4（当前等权平均） |
| 点位容差 | 吸附容差按井配置，超出即不映射，但未映射点的影响未做敏感性分析 |

### U5 Step4 分段预测 + 同井合并

#### 1. 这一步是干什么的

用成像井上学到的"侧向电阻率→裂缝"的规律，对常规井**逐段**预测裂缝，
再把同一口井各段的结果合并成**一条井级裂缝曲线**和**一组井级裂缝点**。
这是阶段一的终点，也是阶段二唯一的井上约束来源。

**角色定位**：学规律 + 输出井级裂缝位置。

**与砂砾岩的关系**：**因数据不同而改造**。砂砾岩按"两个地层 × 三组电阻率"训练六个专家；
太古界只有深/浅电阻率（RD/RS）一组，因此是两个地层专家。

#### 2. 输入（要什么信息）

| 需要的信息 | 来自哪里 | 关键口径 | 规模量级 |
|---|---|---|---|
| 成像监督标签 | U4（Step3） | 连续密度 + 真实点位 | 8 组 / 6 井 / 28,751 行 |
| 分段测井曲线 | U3（Step2） | 逐行三曲线 | 29 段 / 53,394 行 |
| 标签与合并参数 | 项目配置 | 标签阈值、合并容差 | — |

#### 3. 处理逻辑（重点）

##### 3.1 主流程（八个小步）

**(a) 组标签与段曲线对齐**

- 做什么：把监督组里的每一行，按"井 + 垂直深度 + 所属段"精确对到段文件上取三条曲线。
- 为什么必须做：监督标签来自成像解释，曲线来自测井，只有对齐到一个深度点上才能训练。
- 判据/参数：三条键精确连接（不允许模糊匹配），保证一一对应。

**(b) 标签分三类**

- 做什么：把深度点分成"明确有裂缝""明确没裂缝""不确定"三类：
  密度高于该组正样本分位、或落在真实点位邻域内的算明确正；
  密度为零且离真实点足够远的算明确背景；其余算不确定。
- 为什么必须做：如果把手里的模糊点也当训练标签，会把噪声教给模型。
- 判据/参数：正样本取密度 0.5 分位以上 + 真实点 ±0.5 m；背景取零密度且距点 >0.75 m。

**(c) 两个地层专家、各自两阶段**

- 做什么：上部复合层与风化壳各训一个专家；每个专家分两步：第一步判断"有没有裂缝"，
  第二步只在"有裂缝"的样本上判断"有多密"；最终密度 = 存在概率 × 条件密度。
- 为什么必须做：裂缝是"先有/没有、再密不密"的两层问题；混成一步会让大量零值主导回归。
- 判据/参数：条件密度回归只用正样本；最终密度有上限（15）防止异常外推。

**(d) 特征工程：三类特征**

- 做什么：给每个深度点造三类特征——
  ① 曲线本身（伽马、深/浅电阻率的稳健标准化、秩、对数变换）；
  ② 深度局部变化（沿深度的梯度、0.5/1/3/5 m 窗口内的局部残差与离散度）；
  ③ 相互作用（伽马异常与电阻率异常的乘积、深浅对比等）。
- 为什么必须做：单点数值不足以描述裂缝响应，"相对周围怎么变"往往更关键。
- 判据/参数：**窗口类特征只在同一测井段内部计算**（不跨批次），标准化在"井×地层"内进行。

**(e) 按井留一验证**

- 做什么：每次留出一口井做验证，用它训练其余井。
- 为什么必须做：同一口井的相邻深度高度相似，按深度随机切分会让指标虚高。
- 判据/参数：上部复合层 5 折（5 口井）、风化壳 2 折（2 口井）。

**(f) 逐段预测**

- 做什么：对每个段文件的每一行做预测（只对三条曲线齐备、且落在目标地层内的行）。
- 为什么必须做：曲线不齐或不在目标层的行没有预测依据；**不预测、不补零**。
- 判据/参数：输出段行级明细，保留每条行属于哪个段。

**(g) 同井合并（这一步的关键动作）**

- 做什么：把同一口井、不同测次在**垂直深度上相邻**的预测行并成同一个深度点，
  对坐标、曲线、预测值取平均；记录参与合并的测次数量与来源段。
- 为什么必须做：一口井只能有一条裂缝曲线，否则下游（外推、井控）会拿到重复深度。
- 判据/参数：邻域容差 0.25 m；**只合并不同测次之间的近邻行**（同一次测井内部不降采样）；
  当前权重为等权，配置可调。

**(h) 从合并曲线提取裂缝点**

- 做什么：按"密度积分折算点数"的标定方式，在每个阳性段里挑出若干个点，
  保证每段至少一个点。
- 为什么必须做：裂缝点要用来做井控与展示，数量要可控且与密度量级一致。
- 判据/参数：按地层用"真实点数量 / 密度积分"标定；每个阳性支持段至少一点；
  点表**带井级坐标与地震时间**（这是阶段二直接可用的形式）。

##### 3.2 关键判据与阈值表

| 判据 | 取值 | 为什么这样定 | 依据 |
|---|---|---|---|
| 组-段连接键 | 井 + 垂直深度 + 段 | 必须一一对应，不能用模糊匹配 | 实现要求 |
| 明确正样本 | 密度 0.5 分位以上 或 真实点 ±0.5 m | 只把有把握的点当正样本 | 配置 |
| 明确背景 | 零密度且距真实点 >0.75 m | 远离已知裂缝点且密度为零 | 配置 |
| 密度上限 | 15 | 防止模型外推出异常大值 | 配置 |
| 特征窗口 | 段内计算 | 保证窗口内是同一批次的连续观测 | 2026-09-16 决策 |
| 标准化分组 | 井 × 地层 | 让不同测次之间可比，又不丢全局相对水平 | 2026-09-16 决策 |
| 合并容差 | 0.25 m | 同一深度点在不同测次的记录会有小差异 | 配置 |
| 合并权重 | 等权（可调） | 初版占位；原设计写明"跑完按重叠区一致性再定"，**尚未标定** | 设计文档 |
| 支持段断口 | 0.5 m | 缺口过大不跨接，避免造出连续段 | 配置 |
| 裂缝点 | 每阳性段至少 1 个 | 保证段级不漏报 | 设计 |

##### 3.3 用大白话再过一遍

> 我们在成像井上学"电阻率低、伽马异常的地方容易有裂缝"，然后拿着这套规律去给每口常规井
> **每一段测井**分别打分。打分分两步：先判断"这个深度有没有裂缝"，再对有裂缝的深度判断
> "大概有多密"。因为一口井可能测过好几次，最后要把几次的结果按深度对齐合并成一条曲线，
> 并从这条曲线上挑出一批"裂缝点"。

#### 4. 输出（产出什么信息）

| 产出 | 内容 | 给谁用 |
|---|---|---|
| **井级合并密度曲线** | 每口井一条曲线，唯一键＝井 + 垂直深度；含 X/Y/时间、曲线值、参与合并的测次数与来源段 | **Step5 的弱监督来源** |
| **井级裂缝点** | 从合并曲线提取的点，含 X/Y/时间与所属支持段 | **Step8 的井控输入** |
| 段行级预测明细 | 每条段行的预测（含段身份） | 诊断与追溯 |
| 逐井预测目录、验证指标、重叠诊断、覆盖 QC、manifest、验收 | — | 审计 |

#### 5. 怎么判断这一步做对了

- **硬门槛**：合并表唯一键成立（井 + 垂直深度无重复）；坐标与密度有限；
  支持段不跨越大于 0.5 m 的缺口；裂缝点都落在支持段内；验证按井分组（无同井泄漏）；
- **当前结果**：合并曲线 45,830 行 / 17 井，其中 15% 的行由多个测次合并而来；
  裂缝点 4,553 个（其中 17% 来自多测次合并点）。

#### 6. 与前后步骤的关系

- **上游**：U4 的监督标签、U3 的段文件。
- **下游**：Step5 用井级曲线做弱监督、用成像组做强监督；Step8 用裂缝点做井控。
- **重跑影响**：模型、标签或合并规则一旦变化，Step5 及其后**全部**步骤都要重建。

#### 7. 对外解释要点（是什么 / 不是什么）

1. **"先分段预测、再同井合并"是这一步的核心设计**：分段是为了保证每次测井内部的规律一致，
   合并是为了给出一口井唯一的一条曲线。
2. **合并时重叠区取的是平均值**（当前等权），所以重叠区的曲线不是任何单次测井的原始响应，
   而是两次观测的综合。
3. **裂缝点不是观测值**，是按"密度积分折算"从曲线上反推出来的。
4. **模型指标偏弱，属于弱监督基线**：上部复合层 5 折 AUC 0.434–0.651（池化 0.427）；
   风化壳 2 折 0.471/0.477（池化 0.218，低于随机）。当前只作为基线，不做强地质解释。

#### 8. 已知局限与待确认

| 项 | 说明 |
|---|---|
| 风化壳指标低于随机 | 池化 AUC 0.218；且训练井只有 2 口，样本极少 |
| 合并权重未标定 | 等权是初版占位；重叠段对的一致性实测 0.18–1.00（个别对相关性很低） |
| 训练井少 | 只有 6 口成像井参与训练，其中风化壳仅 2 口 |
| 特征口径刚变更 | 窗口特征已改为"段内计算"（r3 验证中），模型与指标会有变化 |
| 密度绝对值不可比 | 各井密度口径不同（见 U4），预测密度的绝对量级只能相对看 |

### U6 Step5 虚拟井与统一训练样本

#### 1. 这一步是干什么的

真实井太少，不足以让模型学会"地震属性长什么样＝裂缝有多密"。所以在每口真实井旁边，
按地震道的位置造一批"虚拟井"，用属性的相似程度判断"井上的裂缝信息能不能搬到旁边去"，
再把真实井样本与通过判断的虚拟井样本按权重拼成一张训练表。

**角色定位**：造阶段二的训练样本（连接"井上裂缝"与"地震属性"的桥梁）。

**与砂砾岩的关系**：**因数据不同而改造**。砂砾岩用四种地震信息（三种属性 + 原始振幅）
且规定"虚拟点的强度只能比源点低"；太古界只用三种属性，并引入"证据强度倍率"——
如果虚拟位置的属性证据比源井更强，允许给出更高的密度。

#### 2. 输入（要什么信息）

| 需要的信息 | 来自哪里 | 关键口径 | 规模量级 |
|---|---|---|---|
| 井级裂缝曲线 | U5（Step4） | 井 + 垂直深度唯一；含 X/Y/时间 | 45,830 行 / 17 井 |
| 成像监督组 | U4（Step3） | 逐段行 + 真实点位 | 8 组 / 28,751 行 |
| 属性值 | 外部属性体 + 公共层证据合同 | 三属性 → 0–1 分数 | 215 万道主网格 |
| 逐道层位合同 | U1（公共层） | 每条道的顶/中/底 | 全网格 |
| 井元数据 | U3（Step2） | 井型、借用时深标记、坐标 | 17 井 |

#### 3. 处理逻辑（重点）

##### 3.1 主流程（九个小步）

**(a) 选井**

- 做什么：11 口常规井进入虚拟井构造；6 口成像井只在井上做预测、不造虚拟井。
- 为什么必须做：成像井的地震时间是借来的，按借用时间造虚拟井会把误差放大。
- 判据/参数：井必须落在属性网格覆盖内；成像井排除出虚拟井范围。

**(b) 取 5×5 邻域**

- 做什么：以源点所在的地震道为中心，取横纵各 5 条道，共 25 个虚拟位置
  （中心道保留，因为真实井位置通常不在地震道正中心）。
- 为什么必须做：真实井与地震道不在同一位置；只用一个最近道会把位置误差当成地质差异。
- 判据/参数：邻域半径 2（即 5×5 = 25 条）；每个源点的 25 个子样本权重之和不超过 1。

**(c) 重算虚拟位置的时间**

- 做什么：先算源点在所属地层内的相对位置（从上界面往下走了百分之几），
  再到虚拟位置的层位面上按同一比例算出虚拟点的时间。
- 为什么必须做：直接照搬源点的时间，会让虚拟点落到错误的深度位置
  （地层是起伏的，几十米横向距离就可能差出几十毫秒）。
- 判据/参数：时间偏移超过 60 ms 的候选点不转成训练样本。

**(d) 采属性并换算成证据分数**

- 做什么：在虚拟位置读取三种属性值，按公共层的证据合同换算成 0–1 的"支持裂缝程度"。
- 为什么必须做：属性量纲与方向不同，必须统一成可比较的尺度。
- 判据/参数：蚂蚁高值=高证据；相干低值=高证据；曲率取绝对值后高值=高证据。

**(e) 算连续性（标签能不能搬）**

- 做什么：把源点与虚拟点的三种证据分数逐个比较，差异越小分越高，再加权平均成"连续性"。
- 为什么必须做：如果虚拟位置的属性和源井位置差得太远，说明两边地质条件不同，
  井上的裂缝结论不能直接搬过去。
- 判据/参数：权重为曲率 0.70 / 相干 0.15 / 蚂蚁 0.15（曲率主导小尺度）。

**(f) 门控与剔除**

- 做什么：主曲率缺失、或有效属性数量不足的候选点直接剔除，并记录原因。
- 为什么必须做：曲率是小尺度的主导证据，缺它就无从判断；这类点不能当负样本。
- 判据/参数：至少 2 个属性有效；被剔除的候选点全部进审计表，不进训练表。

**(g) 双标签**

- 做什么：存在标签直接继承源井（有/无裂缝）；密度标签只在"有裂缝"的虚拟点上给出，
  数值＝源井密度 × 证据强度倍率。
- 为什么必须做：负样本的密度必须是"空"，不能用 0 冒充（0 表示"测到且没有"）。
- 判据/参数：倍率＝exp(β × 证据差)，被限制在 0.25–4 倍之间；β=0.25。

**(h) 权重分配**

- 做什么：每个虚拟样本的权重＝置信度 / 25；置信度＝距离衰减 × 连续性。
- 为什么必须做：25 个虚拟子样本如果各自算一整份权重，就会压过真实井样本。
- 判据/参数：权重上限保证"一口井的虚拟样本总权重 ≤ 真实样本的 5 倍"。

**(i) 并入成像强监督**

- 做什么：把成像组的监督行按其所属段回接坐标后，一并写进统一训练表。
- 为什么必须做：成像监督是"真值"，训练表里必须包含它们，且能与弱监督区分开。
- 判据/参数：逐段回接（不跨段、不平均）；只有勘区内的成像行进入训练表，其余进审计。

##### 3.2 关键判据与阈值表

| 判据 | 取值 | 为什么这样定 | 依据 |
|---|---|---|---|
| 虚拟邻域 | 5×5 = 25 条 | 覆盖井周一圈道位置，中心道保留 | 配置 |
| 时间偏移上限 | 60 ms | 超过说明虚拟点落到了别的深度段 | 配置 |
| 连续性权重 | 曲率 0.70 / 相干 0.15 / 蚂蚁 0.15 | 小尺度由曲率主导 | 需求口径 |
| 有效属性数下限 | 2 | 单属性不足以判断相似性 | 配置 |
| 证据倍率 | exp(0.25×证据差)，限 0.25–4 倍 | 允许虚拟点证据更强时提高密度 | 配置（**未标定**） |
| 置信度 | 距离衰减 × 连续性 | 越远、越不像，越不可信 | 配置 |
| 权重 | 置信度 / 25 | 保证 25 个子样本权重之和 ≤ 1 | 配置 |

| 强监督回接 | 逐段精确匹配 | 每行只在自己所属的段内取坐标 | 2026-09-16 决策 |

##### 3.3 用大白话再过一遍

> 井太少，学不出"属性长什么样＝裂缝多密"。所以我们在每口井旁边按地震网格的位置
> 造出 25 个"虚拟井"。虚拟井的位置变了，地层深度也会跟着变，所以要按它在层内的相对位置
> 重新算时间；然后在那个位置读三种属性的"支持裂缝程度"，跟源井对比：
> 越像，说明井上的裂缝结论越能搬过去。搬过去以后，密度值再按证据强弱做一个微调。
> 这些虚拟样本的权重被压低到真实样本的 1/25，避免"假井淹没真井"。

#### 7. 对外解释要点（是什么 / 不是什么）

### U7 Step6 多尺度三维证据体（6A–6D）

#### 1. 这一步是干什么的

用 U6 的样本学出**三种尺度**的空间证据：小尺度裂缝密度体、中尺度裂缝带、大尺度断层，
再把中/大尺度构造周边的"损伤带"影响范围单独算出来，供小尺度采样时参考。

**角色定位**：造空间证据。

**与砂砾岩的关系**：**因数据不同而改造**（三属性替代四类地震信息；层位换成三界面 + 延伸窗），
流程结构（A/B/C/D 四个子步与各自的时间采样）**直接借用**。

#### 2. 输入（要什么信息）

| 需要的信息 | 来自哪里 | 关键口径 | 规模量级 |
|---|---|---|---|
| 训练样本 | U6（Step5） | 双标签 + 三属性 + 权重 | 506,471 行 |
| 属性证据分数 | U1（公共层） | 0–1 分数 + 分层定标 | 演示区 160,801 道 |
| 逐道层位合同 | U1 | 顶/中/底 + 层窗 | 全网格 |
| 原始断层几何 | U1 的断层片库 | 三角面（不是线段） | 4,494 片 |

#### 3. 处理逻辑（重点）

##### 3.1 主流程（四个子步）

**(a) 6A：小尺度裂缝密度体（曲率主导）**

- 做什么：按地层各训一个"两阶段模型"——先判断有没有裂缝，再对有裂缝的位置判断有多密；
  两者相乘得到连续密度；然后对整个演示区逐道逐样点预测，输出 2 ms 的密度体。
- 为什么必须做：这是阶段二唯一的连续密度来源，后面所有裂缝片都从它采样。
- 判据/参数：特征＝三属性证据分数 + 5 个"位置/地层几何"特征；密度上限 15；
  按井分组留一验证（上部复合层 5 折、风化壳 3 折，保证同一口井及其虚拟子井不跨折）。

**(b) 6B：中尺度裂缝带（蚂蚁主导）**

- 做什么：在 10 ms 时间轴上，用"蚂蚁高值 + 低相干 + 曲率"的加权分数找连续的中尺度裂缝带；
  先用强蚂蚁点做种子，再按较低门槛向周围生长，最后做三维连通与形态过滤。
- 为什么必须做：井上的常规测井只能反映小尺度裂缝，中尺度裂缝带必须从地震属性里找。
- 判据/参数：权重 蚂蚁 0.70 / 低相干 0.15 / 曲率 0.15；种子门槛 0.62、生长门槛 0.52；
  组件最小 50 个体素、倾角 ≥20°、线性度 ≥1.12、平均得分 ≥0.55；顺层异常要被剔除。

**(c) 6C：大尺度断层（相干主导）**

- 做什么：两条来源——① 甲方给的原始断层，作为**硬约束**原样保留；② 从低相干为主的属性证据里
  推断出的断层面（先找三维连续的低相干片，再在片内拟合局部面并分块）。
- 为什么必须做：大尺度断层是裂缝网络的主干，既要用已知解释，也要把属性里明显但没被解释出来的补上。
- 判据/参数：推断断层权重 低相干 0.75 / 蚂蚁 0.15 / 曲率 0.10（在脚本默认值里）；
  必须三维连通、连续成片；与已知断层重合的面要做重复分类后剔除。

**(d) 6D：损伤带上下文**

- 做什么：把中尺度裂缝带、原始断层、推断断层的范围在空间和时间上外扩并衰减，
  形成一张"大构造周边影响范围"的 10 ms 上下文。
- 为什么必须做：断层/裂缝带附近地层更破碎，小尺度裂缝会更发育；这个"晕圈"要靠它表达。
- 判据/参数：紧凑模式，只输出一个 npz（10 ms 轴 + 各来源编码）。

##### 3.2 关键判据与阈值表

| 判据 | 取值 | 为什么这样定 | 依据 |
|---|---|---|---|
| 6A 验证分组 | 按源井分组 | 真实井与其虚拟子井不能跨折，否则指标虚高 | 配置 |
| 6A 密度上限 | 15 | 防止外推异常值 | 配置 |
| 6B 权重 | 蚂蚁 0.70 / 低相干 0.15 / 曲率 0.15 | 中尺度由蚂蚁主导 | 需求口径（配置内） |
| 6B 组件门槛 | ≥50 体素、倾角 ≥20°、线性 ≥1.12 | 过滤噪声与顺层假象 | 配置 |
| 6C 权重 | 低相干 0.75 / 蚂蚁 0.15 / 曲率 0.10 | 大尺度由相干主导 | **脚本默认值，未进配置** |
| 6C 原始断层 | 原样复制、不裁剪、不片化 | 甲方解释是硬约束，不能改 | 设计 |
| 时间采样 | 6A 用 2 ms；6B/6C/6D 用 10 ms | 小尺度需要细采样，中大尺度不需要 | 设计 |

> 先用井上样本学出一张"三维裂缝密度"的体，它主要反映曲率看到的小尺度信息。

> 以后在它附近采样小裂缝时会更密一些。

#### 7. 对外解释要点（是什么 / 不是什么）

1. **小尺度密度体是"模型算出来的"**，不是地震体直接测量结果；它的绝对量级受标签口径影响。

#### 1. 这一步是干什么的

| 需要的信息 | 来自哪里 | 关键口径 | 规模量级 |

#### 3. 处理逻辑（重点）

##### 3.1 主流程（四个子步）

**(a) 7A：小尺度裂缝片**

- 做什么：在密度体上按"分层加权概率"抽点作为裂缝片中心（密度高的地方更容易被抽到），
  再按空间最小间距做去重；方向优先用成像井的真实方位先验，其次用局部梯度/PCA。
- 为什么必须做：密度体本身只是一团数值，要变成能参与井控和展示的几何片。
- 判据/参数：出现概率 上部复合层 0.015 / 风化壳 0.01；候选分位 0.9；中心最小间距 20 m；
  倾角限制在 25–89°（避免近水平片冒充裂缝）。

**(b) 7B：中尺度裂缝片**

- 做什么：在 6B 的每个组件内部选点生成裂缝片：大部分沿蚂蚁体"脊线"（最明显的部分）取，
  其余按空间覆盖补点；方向用局部 PCA。
- 为什么必须做：只按最高分位置取点会让裂缝带在剖面上显得断断续续。
- 判据/参数：脊线优先比例 0.6；每个组件 2–10 片；脊线间距 50 m；全局最小中心间距 45 m；
  片长目标中位 80–100 m、上限 145 m。

**(c) 7C：大尺度断层**

- 做什么：把甲方原始断层三角面**原样复制**并校验几何指纹不变；把属性推断出的断层面
  转成大尺度片；与原始断层重合的部分单独分类剔除。
- 为什么必须做：原始断层是硬约束，任何"重新生成"都可能改变甲方解释。
- 判据/参数：原始断层不做层位裁剪、不做片化；复制前后 SHA256 必须一致；
  已知断层重复片剔除（本次 19 片）。

**(d) 7D：多尺度融合**

- 做什么：把小/中/大三张片表合并成一张（保留各自的尺度标签），再把原始断层三角面
  作为**第二个几何组**追加到统一三维文件里。
- 为什么必须做：下游只需要一个文件、一个片表；同时必须让"预测几何"和"原始解释"
  在同一个文件里可区分地共存。
- 判据/参数：融合前必须确认大尺度文件里仍含原始断层组；统一文件用几何组编号区分
  （1＝预测片、2＝原始断层）。

| 判据 | 取值 | 为什么这样定 | 依据 |
|---|---|---|---|
| 7A 出现概率 | 0.015 / 0.01（分地层） | 控制片数量，避免过密 | 配置 |
| 7A 最小间距 | 20 m | 保证片在空间上不重复 | 配置 |
| 7A 倾角 | 25–89° | 近水平片多为层理假象 | 配置 |

##### 3.3 用大白话再过一遍

> 密度体只是一堆数字，我们要把它变成一片片"裂缝"：在密度高的地方按概率抽点，
> 每片给一个大小和方向——方向优先参考成像井里真实裂缝的走向。中尺度裂缝从蚂蚁体找出的
> 裂缝带里成片取；大尺度断层则分成两部分：甲方解释的原样保留，属性里推断出来的另外存。
> 最后把所有片子和原始断层放进同一个三维文件，用编号区分"哪是算出来的、哪是解释给的"。

### U9 Step8 井控校正

#### 1. 这一步是干什么的

用**井上的裂缝证据**去校正模型预测的裂缝片：井附近的小尺度片可以移动或新增，
井周围密度可以软增强；中尺度、大尺度和甲方原始断层一律不动。

**角色定位**：校正。

**与砂砾岩的关系**：**结构直接借用**（"只动小尺度、成像真值优先、井周软增强"），
参数按太古界的层厚与井数重新设定。

#### 2. 输入（要什么信息）

| 需要的信息 | 来自哪里 | 关键口径 | 规模量级 |
|---|---|---|---|
| 融合裂缝片与统一文件 | U8（Step7D） | 含预测组与原始断层组 | 26,728 片 |
| 井上裂缝点 | U5（Step4） | **自带 X/Y/时间**（井级输出） | 4,553 点 |
| 成像真实点位 | U4（Step3） | 逐段行（需按段取坐标） | 高优先控制 |
| 逐道层位合同 | U1 | 顶/中/底 | 全网格 |

#### 3. 处理逻辑（重点）

##### 3.1 主流程（七个小步）

**(a) 取井上控制点**

- 做什么：直接读取第 4 步输出的井级裂缝点——它们本身就带坐标与地震时间；
  成像的真实点位则按"它属于哪一次测井"逐段取坐标。
- 为什么必须做：控制点必须有正确的空间位置才能和裂缝片匹配；
  早期版本因为点表缺坐标，只能靠深度反查、容易出错。
- 判据/参数：井级点直接取坐标；成像点逐段回接（不跨段、不平均），未命中进审计。

**(b) 把密集的井上点聚成"事件"**

- 做什么：把同一口井、同一地层里时间上紧挨着的预测点合成一个"裂缝事件"。
- 为什么必须做：测井预测点是等间距的，密度高的井段会产生成百上千个点；
  不聚合会让几十片裂缝挤在一小段里。
- 判据/参数：间隔 ≤6 ms、事件总跨度 ≤18 ms；事件的密度取组内最大值。

**(c) 成像真值优先**

- 做什么：在成像解释覆盖的时间窗内，用成像真实点位替换井上预测点。
- 为什么必须做：同一段深度如果既用预测又用真值，会重复布置裂缝。
- 判据/参数：成像窗内替换；窗外保留预测点。

**(d) 层位窗口筛选**

- 做什么：检查每个控制点的时间是否落在"它所属地层的顶底之间"，不在的排除并审计。
- 为什么必须做：控制点如果落在层外，说明位置或时间有问题，不能用来校正。
- 判据/参数：按逐道层位合同的顶/中/底判断；**注意**：成像井的时间是借来的，
  这一步会因此误剔部分真实点（见局限）。

**(e) 匹配与校正（只动小尺度）**

- 做什么：在每片小尺度裂缝里找距控制点最近的一片（水平 ≤80 m、时间 ≤30 ms）——
  找到就把它移到控制点附近并采用控制点的方位/倾角；找不到就新造一片。
- 为什么必须做：井上证据必须体现在几何上，否则模型预测与井上观测会矛盾。
- 判据/参数：新片尺寸 25–80 m / 5–15 ms；中心允许偏移 5–25 m；
  倾向按地层取目标值（上部复合层 55°、风化壳 65°）。

**(f) 成像井周软增强**

- 做什么：在成像真实点周围 150 m / 40 ms 范围内，把已有小尺度片的密度往上抬一点
  （按距离衰减，融合比例 0.65）。
- 为什么必须做：成像证据反映的是"这一带裂缝发育"，不只是单点，周边密度也应体现。
- 判据/参数：只提高、不删除；中/大尺度与原始断层不参与。

**(g) 层位收敛与写出**

- 做什么：对"被移动或新增"的小尺度片，重新按逐道层位把中心时间夹进地层窗内、
  并把顶点裁剪到地层范围内；最后把预测组与原始断层组一起写成统一三维文件。
- 为什么必须做：移动过的片可能压到层界之外；原始断层必须原样带入。
- 判据/参数：只有被改动的片做层位收敛；中/大尺度用几何指纹校验"未被动过"。

##### 3.2 关键判据与阈值表

| 判据 | 取值 | 为什么这样定 | 依据 |
|---|---|---|---|
| 事件聚合 | 间隔 ≤6 ms、跨度 ≤18 ms | 把等间距预测点压成"事件"，避免过密 | 配置 |
| 匹配半径 | 80 m / 30 ms | 井周局部范围；过大会牵动远处裂缝 | 配置 |
| 新片尺寸 | 25–80 m / 5–15 ms | 与小尺度裂缝及本地层厚匹配 | 配置 |
| 中心偏移 | 5–25 m | 避免所有片都精确穿过井轨迹 | 配置 |
| 倾向目标 | 上部复合层 55°、风化壳 65° | 与成像先验一致 | 配置 |
| 井周软增强 | 150 m / 40 ms、融合 0.65 | 成像证据的邻域影响 | 配置 |
| 可改动范围 | 仅小尺度 | 中大尺度与原始断层是地质主体 | 设计 |

##### 3.3 用大白话再过一遍

> 模型先算出一堆裂缝片，但井上是有真实观测的。于是我们把井上预测的点（密集的合成"事件"）、
> 成像井解释出的真实点，都当成"约束"：在井附近，如果已经有小裂缝片，就把最近的一片挪到
> 观测点旁边并采用观测到的方向；如果附近没有，就新造一片。成像井周围一定范围内的裂缝密度
> 会适当调高。中尺度、大尺度和甲方给的断层一律不动。

#### 3. 处理逻辑（重点）

**(a) 读几何与校验**

- 做什么：读统一三维文件里的预测片组，并确认原始断层组存在；片元数据从表里取。
- 为什么必须做：展示必须基于"校正后的最终 DFN"，且必须能区分预测与原始断层。
- 判据/参数：文件必须同时含两类几何组，否则直接报错。

**(b) 构造弯曲剖面**

- 做什么：沿井轨迹构造两个方向的剖面（一个沿 X 看、一个沿 Y 看），
  纵轴是地震时间，横轴是沿剖面的水平坐标。

  原始断层单独用另一种线型画。
- 为什么必须做：线段能反映裂缝的倾斜方向，散点看不出方向；两类几何必须能区分。
- 判据/参数：片可在剖面附近一定范围内投影（总览 50 m、井周 200 m）。
