## 1. 背景：为什么要统一口径

剖面上"成像测井粉色产状短线"和"DFN 橙色裂缝片"的走向对不上，且不是固定差一个角度，
而是**有时接近平行、有时接近垂直**。逐行核查后确认：不是数据问题，是**方位口径在链上被混用**。

甲方原始裂缝文件里的角度是 **真倾向方位**（回答"缝往哪边倒"，罗盘 0–360），
而我们造片、建三维顶点用的字段被当成 **走向**（回答"缝往哪边躺"）和 **XY 平面角**
（自东逆时针）使用。这三者两两相差 90° 或成镜像。

### 1.1 仓内实测：三套口径并存

坐标约定：**X=东、Y=北**（UTM：X≈66.6 万、Y≈424.2 万；`太古界/step9_sections` 的
`apparent_dip_trace` 文档字符串也是这么声明的）。

| 环节 | 代码写法 | 实际口径 |
|---|---|---|
| 甲方原始裂缝文件 | `Dip Azimuth` 列 | 真倾向方位（罗盘 0–360） |

### 1.2 核心换算（已数值验证）

给定真倾向方位 `D`、倾角 `δ`：

- 面法向（x=东, y=北, z=上）：`n = (sinD·sinδ, cosD·sinδ, cosδ)`
- 罗盘走向：`S = (D - 90) mod 180`
- 旧代码"长边方向角"`A`（`strike=[cosA, sinA]`）的正确取值：
  `A = (180 - D) mod 180`，等价于 `A = (90 - S) mod 180`

验证表（"真走向"= 由 `n` 反算的罗盘走向）：

| D | δ | 真走向 | A=(180−D) | A 造出的长边罗盘方位 | S=(D−90) | A=(90−S) 造出的长边方位 |
|---|---|---|---|---|---|---|
| 145.0 | 70.0 | 55.0 | 35.0 | 55.0 | 55.0 | 55.0 |
| 128.0 | 35.0 | 38.0 | 52.0 | 38.0 | 38.0 | 38.0 |
| 221.5 | 76.1 | 131.5 | 138.5 | 131.5 | 131.5 | 131.5 |
| 0.0 | 60.0 | 90.0 | 0.0 | 90.0 | 90.0 | 90.0 |

**结论**：`A=(180−D)%180` 与 `A=(90−S)%180` 完全等价，都能把长边放回真走向。

### 1.3 现状误差量级

太古界 7A 家族角（md1 正式）：`162.5° / 16.8° / 79.0°`（上部复合层）、`138.3° / 11.5°`（风化壳）。
这些是甲方**真倾向方位**，被当走向用。

`md2_azfix2` 改成 `(FracAzimuth + 90) % 180` → `72.5° / 106.8° / 169.0°`，
那是**罗盘走向**；而 7A/7B/7C 的顶点构建需要的是 `(180−D)%180` → `17.5° / 163.2° / 101.0°`，
**仍差 55°**。这就是"改了 90° 还是不对"的原因。

### 1.4 砂砾岩对照（只作参考，不作为正确样本）

- 砂砾岩 7A 产状**不来自成像测井**：69% 用每层手工模板（沙三 55°/70°、沙四 125°/68°），
  31% 用局部密度 PCA；7A–7D 脚本中 imaging/井控引用计数为 **0**。
- 剖面实际画出（罗盘走向）：沙三段 DFN 32.3° vs 粉线约 105°（差 73°，看着垂直）；
  沙四段 DFN 130.1° vs 粉线 119.7°（彼此差 10°，但都偏真值 60–70°）。
- 砂砾岩"看着没那么离谱"的原因：52274 片里只有 262 片井控，其中仅 60 片用成像产状（0.11%）。
- 结论：砂砾岩只能当**流程骨架**参考；它的 Step9 成像画法反而不如太古界（太古界的
  `apparent_dip_trace` 是全项目唯一物理正确的实现）。

## 3. 口径定义（施工判据，唯一标准）

| 量 | 定义 | 谁用 | 禁止 |
|---|---|---|---|
| **`DipAzimuthDeg`** | 真倾向方位，`[0,360)`，自北顺时针。来自甲方 `Dip Azimuth` 原义 | Step7A/7B/7C/7D/8 片表、Step9 绘制、全部 QC | 不得再存"走向"或"平面数学角" |
| **`StrikeDeg`** | 派生走向 `(DipAzimuthDeg − 90) mod 180` | 图例、报告、需要 axial 的下游 | 不得由其他口径直接赋值 |
| **`AzimuthDeg`** | 一期保留为 `StrikeDeg` 的同义别名（避免一次性改爆下游） | 兼容旧消费者 | 不得再直接参与几何计算 |
| **`DipDeg`** | 倾角 `(0,90]` | 同上 | — |
| **几何帧** | `x=东, y=北, z=上`；`1 ms = 2 m`（`TIME_SCALE_M_PER_MS`） | 法向、顶点、剖面交线 | 不允许局部另立坐标系 |

**唯一换算入口**：`太古界/common/orientation_frame/convention.py`。
业务脚本里**不允许再出现裸 `atan2(...)` 算方位**。

## 5. 施工步骤

### S1 新建公共换算模块（`太古界/common/orientation_frame/`）

新增 `__init__.py`、`convention.py`，提供且**仅提供**以下函数：

| 函数 | 作用 |
|---|---|
| `normal_from_dip_azimuth_dip(dip_azimuth_deg, dip_deg)` | `(D,δ) → n=(sinD·sinδ, cosD·sinδ, cosδ)` |
| `dip_azimuth_dip_from_normal(normal)` | `n → (D∈[0,360), δ∈[0,90])` |
| `strike_from_dip_azimuth(D)` | `D → (D−90)%180` |
| `dip_azimuth_from_strike(S)` | `S → (S+90)%360` |
| `xy_line_angle_from_strike(S)` | `S → (90−S)%180`（建立旧式 `[cosA,sinA]` 几何用） |
| `strike_from_xy_line_angle(A)` | `A → (90−A)%180`（把历史产物换算到罗盘走向） |
| `trace_on_section(D, δ, projection)` | 裂缝面 ∩ 剖面面交线方向 `(水平分量, TIME 分量)`，**即现 `apparent_dip_trace`** |

**验收判据**：单测（`太古界/common/orientation_frame/test_convention.py`）全绿——

1. 往返：`dip_azimuth_dip_from_normal(normal_from_dip_azimuth_dip(D,δ)) == (D,δ)`，1e-9；
2. 一致：`normal_from_dip_azimuth_dip(D,δ)` 与 `xy_line_angle_from_strike(strike_from_dip_azimuth(D))`
   造出的面，其反算走向相同；
3. 交线：`trace_on_section` 在 XZ/YZ 下的视倾角，与闭式 `tanβ=|sinα|·tanδ`(XZ) / `|cosα|·tanδ`(YZ)
   逐点最大差 ≤ 1e-9（沿用 §0.29 的验证方法）；
4. 覆盖边界值 `D ∈ {0, 45, 90, 135, 180, 225, 270, 315, 359.9}`、`δ ∈ {1, 45, 89}`。
