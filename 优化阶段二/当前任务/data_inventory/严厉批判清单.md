  - 可执行要求：把“主属性体全部无效”“中心点无效”“3x3 全无效”定义成脏点规则，形成剔除或隔离清单。

## 15. `3x3` 明细表只证明行数对了，根本没证明取到的是“真实空间九点”

- 事实依据：
  - 当前验证强调的是 `20 x 5属性 x 9邻域 = 900` 这种行数关系。
  - 但行数正确只说明表被写出来了，不能证明 `NeighborX/NeighborY` 真的是围绕井点按 `12.5m` 展开的九个真实坐标，也不能证明这些坐标确实从体里采到了值。
- 批判：
  - 这是把“格式正确”当成“数据正确”的又一次偷换。
  - `3x3` 表最核心的不是 45 行，而是九个平面点位有没有真实坐标、真实偏移、真实插值结果；只盯行数是在避开真正的空间正确性问题。
  - 可执行要求：后续必须把每个样本至少抽查一组 `OffsetX/OffsetY/NeighborX/NeighborY/AttributeValue` 的空间一致性，不能再用行数充当质量证明。

## 16. 输出结构没有把“样本可用性状态”单独做成硬字段，导致无效结果和有效结果混在一起

- 事实依据：
  - 当前主表、`3x3` 表、层位表虽然分开了，但没有把“该点是否可进入后续建模”做成一眼可判的硬字段体系。
  - 结果就是：层位上合法、结构上完整、但体数据全空的点，和真正可用点一起出现在同一套正式样本里。
- 批判：
- 这会直接污染后续所有步骤，因为下游拿到表后无法第一时间区分“可训练样本”和“仅保留痕迹的失败样本”。
- 正式样本入口最怕这种半死不活的状态：既没删掉，也没标明不可用，最后每个下游步骤都得重复踩坑。
- 可执行要求：输出里必须增加统一的可用性状态，例如 `SampleUsableStatus`，至少区分 `usable / dirty_volume / dirty_horizon / dirty_log / skipped`。
